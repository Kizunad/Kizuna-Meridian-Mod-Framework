# 环境真元交换契约

状态：**通用器官摄入、区域库存、共享供给预算和环境/身体原子交换已有 Java 内存参考实现。** [环境配置](Environment-Configuration.md)提供 TOML、chunk 区域及浓度/传播计算。真实世界来源选择、磁盘事务和扩散执行仍由宿主接入；人体器官配置属于独立附属模组。

## 已实现的摄入流程

手动吐纳另使用按浓度计算的[接触摄入](Gathering.md)：`CaptureQi` 经可信命中入口授权，按粒子采样体积和当前环境浓度计算原料，按目录配方比例即时炼化。其 `EnvironmentQiExchange.contact_capture = true`，起止时刻相同；不申请持续摄入带宽，保留来源既有 `usage`，只扣真实库存并归还实际转换损耗。`QiCaptureResult` 随身体、来源和回执原子保存，事务从旧状态复算。普通摄入回执禁止标记为接触事件。

`BodyCommand.intake_qi` 只包含 `organ_id` 和原始 `qi` 明细。`BodyCommandHandler` 在授权、成功回执去重和身体 revision 检查之后，从 `BodyTimeSource` 取得可信目标时刻，再由 `BodyEnvironmentSource` 确认整个区间的来源 ID。客户端不能上传时间、来源库存、速率或转换效率。

```text
身体旧游标 → 可信活动区间 → 器官能力/容量校验
→ 实际区域库存扣除、共享供给预算占用
→ 原始真元进入器官缓存、年龄与游标推进
→ 身体、来源、预算、成功回执一起提交
```

`OrganIntake.apply` 是身体纯算子，`EnvironmentAbsorption.apply` 是环境扣账与预算纯算子；单独调用均不提交。`InMemoryBodyStore.stage` 从旧身体和真实来源重新计算，核对完整候选与回执后才暂存。任一步失败、私有策略拒绝或暂存后回调抛错，都保留旧状态。

器官通过可缺省的 `OrganDefinition.intake` 声明 `max_qi_per_second`；缺省意味着没有摄入能力。该参数独立于器官端口搬运吞吐，随实际构型保存。摄入要求器官及所属部位仍有 HP，身体存活。容量检查包含缓存、加工原料和在途货物的目标预约；整笔超限就拒绝，不静默截断剂量。

原始相态和属性完整保留在器官缓存。当前不在摄入时自动炼化，也不依赖经脉开拓或固定器官名称；没有经脉的生物同样可以配置此能力。首片每条命令处理一个器官和一个来源，同一身体区间由该命令一次消费，多器官同时摄入与自动安排留给后续执行调度。后续用既有配方和运输继续处理，动态按属性炼化效率另行实现。

摄入消费 `[身体 settled_at, 可信 target)`，成功同时推进年龄和游标，身体 revision 只加一次。不能先推进到 target，再补做这段摄入；不能换请求 ID、器官或来源重复使用已结算时间。`LIFESPAN_ONLY` 拒绝摄入。区间内部的加工完成或区间内/末端的寿尽返回 `PENDING_TIME_EVENT`，宿主先拆段；运输到达与自然扩散由时间算子在区间内按事件结算，不切碎有效摄入时间。末端加工可以一起完成，损耗记在同一环境交换中，只入选定来源一次。起点与时间推进后末端均检查摄入空间，包含加工原料及入向预约；任何一步失败，身体时间、运输和环境交换一起回滚。

## 区域库存与共享窗口

`EnvironmentQiSource` 保存唯一库存、空间、来源 revision、供给窗口和已用速率分段。`EnvironmentAbsorption.initialize` 根据 `库存 / 空间体积 × 配置采集体积速度` 生成首个窗口速率；宿主只对尚不存在的来源原子创建。地形生成的 `initial_qi` 可直接作为初始库存，加载已有来源则使用保存值。

当前采用**固定窗口的离散近似**：窗口开启时按浓度确定速率，窗口内部每次交换更新真实库存和版本，但不重置速率或预算；窗口结束后按剩余库存重新计算。窗口长度由可信宿主调度决定，应使用有限的短稳定区间，不能把起点浓度无限积分。整个窗口持续检查真实库存，无法透支或凭释放垫付吸收。

每次请求按 `实际摄入量 / 区间模拟秒数` 占用均匀速率。`EnvironmentQiUsage` 保存所有身体合计的占用曲线：按时间排序、互不重叠，相邻等速分段合并。每个重叠子区间都要求 `已有速率 + 本次速率 <= 窗口上限`，不能仅检查整窗剩余总量。例如四元/秒的区域，甲在 `[0,1)` 已用三元，乙在同区间最多再用一元；乙的区间改成 `[0.5,1.5)` 也不能越过重叠部分的上限。

`EnvironmentProtobuf.encodeSource/decodeSource` 同时保存库存和曲线；曲线不是额外真元。来源 revision 更新、身体重新登录和存档恢复都不清空预算。曲线受协议列表上限限制，超限整笔拒绝，不能遗忘历史用量换取空间。

`InMemoryBodyStore.renewEnvironmentWindow` 供可信宿主在结清旧窗后显式续窗：预期来源 revision 必须匹配，同域同世代且新起点不早于旧终点。续窗保留库存、revision 加一、重新按浓度计算速率，才清除已封闭窗口的占用。尚未结算的旧身体不能倒用新窗；宿主应先完成所有需要保留的旧窗摄入。这个操作不注册客户端入口或后台定时器。

非摄入释放可通过 `creditEnvironmentSource` 记入区域，已经进入默认释放账户的余额则通过 `transferReleasedToSource` 原子归位。每次仅增加库存和来源 revision，窗口、速率与已用预算保持不变；旧 offer 随版本变更失效。宿主宜在续窗边界集中执行并负责释放去重，约束见[宿主接入](Host-Integration.md)。

## 职责与入口

框架负责描述供给、交换及成功回执。宿主根据身体所在世界和位置选择来源，管理区域库存、浓度、扩散、共享供给预算和原子提交。Fabric 单机由内置服务端提供这些事实，Bong 或其他语言宿主使用同一契约。交换消息不绑定坐标格式或某种生物的吸收器官；Java 环境参考规则使用可配置的 chunk 分区。

协议源是 `shared/src/main/proto/kizuna/meridian/v1/environment.proto`；两端由 protoc 生成 `EnvironmentMessages`，与其他协议一起进入 JAR、描述集和协议 ZIP。Java 校验入口是 `EnvironmentProtobuf` 的 Offer、Exchange、Receipt、Source 编解码与验证方法。交换原始 Protobuf 字节，沿用[协议规模与存在性限制](Protocol-and-Security.md)。

这些都是**经过认证的宿主与权威身体实现之间的内部事实**，不属于 `RequestEnvelope`，不能注册为客户端上传入口。消息携带 ID 不构成授权；即使客户端也能生成消息，宿主仍须验证生产方和来源选择。`parseFrom` 只解析格式，`EnvironmentProtobuf` 只校验事实关系，都不会执行转账。

## 三种消息

| 消息 | 字段 | 含义 |
|---|---|---|
| `EnvironmentQiOffer` | `protocol_version` | 当前为 1，与身体 schema 3 和账户 revision 独立 |
| 供给 | `source_id`、`source_revision` | 宿主内跨世界唯一、永久不复用的来源身份，以及非负权威版本 |
| 供给 | `body_id` | 该份供给适用的身体，不能挪给另一具身体 |
| 供给 | `available_qi` | 当前版本允许本次吸收的逐相态、逐属性上限，单位元；可为空 |
| 供给 | `max_absorption_per_second` | 对该身体所有种类合计的吸收上限，元/模拟秒；0 表示仅可释放 |
| 供给 | `valid_from`、`valid_until` | 同一时钟域和世代下的半开有效区间 `[from, until)`，必须有正时长 |
| `EnvironmentQiExchange` | `exchange_id`、`offer` | 权威端生成的稳定交换 ID，以及计算实际采用的完整供给事实 |
| 交换 | `expected_body_revision` | 计算前的身体版本，提交时必须仍匹配 |
| 交换 | `started_at`、`ended_at` | 本次稳定结算区间 `[start, end)`；纯释放可为同一时刻 |
| 交换 | `absorbed_qi`、`released_qi` | 两个方向分别记录的毛额，空方向也显式提供空账户 |
| `EnvironmentQiReceipt` | `exchange` | 已提交的原始交换，保持供给和明细以支持去重与恢复 |
| 回执 | `body_revision`、`source_revision` | 提交后版本，分别为候选中的旧版本加 1 |

供给只是一份带版本的事实，**不预扣资源、不产生新库存，也不预留余额**。它可以只披露实际库存的一部分，不能把 `available_qi` 当作完整区域存档。来源身份、版本和供给策略由宿主管理；位置映射不需要写进通用身体结构。

`optional` 数值在业务上必填，合法的 0 也须显式提供。真元复用 `QiInventory`：允许混相、混属性与第三方属性，同种类只能一行，明细数量为正，空账户用空列表。所有连续数值及总量必须有限，版本使用非负 `int64`。

## 区间与吸收校验

供给窗口和交换的四个时间游标必须同域、同世代。必须满足：

```text
valid_from <= started_at < valid_until
started_at <= ended_at <= valid_until
吸收各类数量 <= available_qi 中的同类额度
吸收总量 <= max_absorption_per_second × (ended_at - started_at) / 1000
```

时间差先按整数毫秒计算，再转换为模拟秒；生物老化倍率不影响吸收速度。吸收必须有正时长，零速率或零时长不能吸收正数真元。纯释放可在有效窗口内瞬时发生，不消耗吸收带宽，也不要求环境已有库存。右端点可以作为区间的结束，不能作为零时长释放的起点；宿主须为该新时刻提供有效供给事实。

数量和速率上限严格比较，不允许供给透支。逐类扣除还检查浮点数能否实际体现这笔扣款，速率与时长乘积溢出时拒绝；宿主可以缩短结算区间。不能通过先抵消释放来通过吸收校验：吸入 2 元并释放 1 元，需要的吸收额度仍然是 2 元。至少一个方向必须有转移，双空交换不能产生成功回执。

一次交换只绑定一个身体和一个来源。来源选择、身体所在位置或供给条件改变时，先结算旧稳定区间，再取得新供给；不能用最终位置的浓度倒推整个离线区间。跨来源的连续运行拆成顺序交换，每次沿用前次提交后的身体版本。

## 宿主提交必须满足的行为

以下是接入方必须实现的事务语义；Java 内存参考已为摄入执行账户和预算部分，世界位置与区间有效性由可信宿主证明。编解码器本身不执行转账：

1. 认证生产方并校验身体访问权。在事务内按 `body_id + exchange_id` 查回执：同键同已解码内容返回原回执；同键不同内容拒绝。不要按 Protobuf 原始字节是否相同判断重试。已成功请求先返回旧结果，不因当前版本或供给过期而重新执行。
2. 隔离身体、来源账户及相关共享供给预算，核对两个预期版本。宿主验证来源确实对应本次身体位置、供给事实没有被伪造，且所用条件在整个区间成立。实时提交检查有效性；离线推演只能使用宿主保存或重建的可信历史区间，不能无限延用已失效的旧供给。
3. 校验身体确实能吸收或释放这些明细。吸收区间必须属于身体本次尚未结算的有效活动时间，不能通过换交换 ID 或获取新供给再次使用已消费的时间。`LIFESPAN_ONLY` 冻结吸收；死亡只清账释放。具体摄入器官、局部容量和开拓规则由身体算子验证。
4. 先按相态和属性从**真实环境库存**扣除 `absorbed_qi`，再加入 `released_qi`。供给额度不能代替真实库存，也不能用同笔释放补足超额吸收。宿主还须检查多个身体在重叠区间内的共享供给额度，已用额度随状态一起保存；换来源 revision 不会重新获得同一时间的带宽。
5. 将新身体、新环境库存、供给预算和成功回执一起原子提交。身体和来源版本分别增加 1；任一版本已到 `Long.MAX_VALUE` 则拒绝。任一步失败全部回滚，不在提交后的审计通知中执行转账。

环境库存、扩散或其他消费者改变供给依据时，宿主更新来源版本，使旧候选重新校验或重算。**来源版本只能防止使用旧事实，不能单独证明带宽没有被重复消费**，因此共享预算和身体已结算时间也属于事务检查。跨进程实现仍须提供同等原子性，Protobuf 本身不提供分布式事务。

幂等键由可信身体身份约束，交换 ID 在该身体生命周期内不复用。回执与两个账户状态一起保存、一起恢复；不得仅靠重放回执恢复已入账资源。没有另行定义过期重试规则前，不清理去重记录。一个交换对应一次身体提交；宿主若将交换并入同次身体命令，两类回执描述同一个身体 revision，不再额外增加一次。

## 守恒与转换

```text
环境新账 = 环境旧账 - absorbed_qi + released_qi   （逐相态、逐属性）
身体新总元 = 身体旧总元 + absorbed_qi.total - released_qi.total
```

`absorbed_qi` 表示从环境取走的原始种类。器官转换后的种类写入身体实际账户，转换损耗作为 `released_qi` 退回环境；损耗仍是真元，不能从总账消失。宿主应按对应身体算子的结果核对明细和总量，不能仅凭上面总量相等就允许伪造属性转换。

释放不自动改变相态和属性。死亡释放保持原种类，当前器官加工损耗按无属性游离态返回；环境内退化和扩散由后续世界实现处理。回执只记录本次越过身体边界的数量，供给事实和回执都不加入身体总元。

摄入回执使用 `CommandReceipt.organ_intake` 保存可信计划及 `EnvironmentQiReceipt`，交换 ID 为 `intake-新身体revision`。回执与新身体、来源一起保存；`time_advance` 在摄入回执中必须缺省，避免加工损耗沿两条路径重复发放。普通时间命令的死亡/加工释放仍先进入参考实现的 `environmentQi()` 默认释放账户；宿主确定世界位置归属后，通过 `transferReleasedToSource` 转入对应区域，不能把未转出的默认账户余额也算作区域库存。

## 当前验证与下一步

整体契约回归覆盖供给固定字节、零值存在性、混相/自定义属性往返、双向毛额、瞬时释放、非法供给、跨时钟与区间、超库存/错种类/超速、浮点极限、版本递增和客户端入口拒绝。两端产物校验确保协议及描述集同步分发。

`InMemoryBodyStoreTest` 覆盖外部入账、默认账户归位守恒、混相/自定义属性存档往返、非法明细、嵌套调用、来源版本耗尽、数值及协议校验失败的整笔回滚。`OrganIntakeTest` 另验证入账后的旧 offer 拒绝、新 offer 正常摄入且共享预算不重置。

`OrganIntakeTest` 保留摄入守恒、非人/无经脉构型、并发与局部重叠预算、续窗不补满、分段一致、恢复不重领、容量预约、加工损耗单次入账、私有策略拒绝及原子回滚等整体回归。[开脉任务](Meridian-Opening.md)已复用真实摄入证据与原子费用；动态按属性炼化、世界位置历史适配、区域扩散调度仍待后续切片。
