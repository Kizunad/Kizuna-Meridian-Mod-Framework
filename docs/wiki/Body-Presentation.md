# 身体展示资源

`shared/src/main/proto/kizuna/meridian/v1/presentation.proto` 定义生物附属与展示附属共用的 Protobuf 资源契约。它独立于权威身体快照，不新增身体写入入口、HP 或真元账本。

`BodyPresentation` schema 1 绑定精确模板 ID 与修订，声明整体包围盒、展示层和三角网格节点。坐标为模型局部米，右手系，Y 向上、Z 向前；具体生物的左右、尺寸和位置由内容包确定。全层使用相同包围盒，切换层不重算身体比例。

每个 `BodyVisual` 包含稳定节点 ID、展示名称、层 ID、三角网格、RGB 颜色，以及 `target_kind + target_id` 身体引用。引用可以指向部位、组织、器官或经脉。多个模型可以绑定同一对象，例如骨架展示绑定已有部位；没有独立骨骼状态时不能虚构骨骼 HP。模型位置不替代权威 `Connection.distance`，经脉曲线也不创建运输连接。

节点可声明 `texture_resource`、逐顶点的 `texture_uv` 和静态 `description`。贴图使用已安装资源包中的 `namespace:textures/...png`，UV 为有限的 `[0,1]` 坐标，数量必须与顶点相同；未声明贴图时 UV 必须为空，仍使用纯色。贴图 RGB 与节点颜色相乘。介绍说明由内容包编写，实时 HP、疲劳和真元仍从权威快照读取。新增字段沿用 schema 1，旧纯色资源仍有效。

拼装关系由生物内容的编辑源持有并在构建期烘焙为统一坐标；UI 可同时勾选多个层，用真实深度完成遮挡与选取。框架不指定器官装配位置，也不加载 Blockbench 编辑文件。

生物附属拥有具体模型和经脉路径；UI 附属负责有界解码、坐标/索引/身份校验、身体引用检查、渲染、选取和聚焦。静态资源通过资源包提供，本阶段没有自动资源下载或网络资源注册。模板不匹配、对象已删除或资源缺失时应给出明确显示反馈，不创建默认人体。

本契约只声明展示结构。主框架生成消息与描述集，不依赖 Minecraft、Inventory UI 或具体生物。跨语言宿主和其他展示器可以使用相同 `.proto`。
