# 聚气与手动吐纳编排

状态：已实现通用单轮聚气协议、可重复手动吐纳和 Java 参考编排；独立 UI 附属提供吐纳窗口与 Inventory UI 公共路由桥接。游戏内开发演示使用真实核心与内存环境账户，生产玩家绑定、世界来源、磁盘存档和宿主事件队列仍由接入方装配。

## 请求与可见状态

`BreathingView.absorbed_qi` 是当前连接累计摄入的原始灵气；`stored_qi` 是手动吐纳批次实际到达经脉的累计炼化产物。两者都不是当前余额。加工尚未完成或货物仍在途时不增加 `stored_qi`，后续消耗不回减；重连从新会话开始统计。UI 的「纳入真元」应使用后者，当前余额统一从 `GatheringView.body` 的唯一账户求和。比如 Human 输入 1 元灵气产出 0.2 元真元，不能把前者当作经脉收货量。

唯一协议源是 `shared/src/main/proto/kizuna/meridian/v1/gathering.proto` 与 `breathing.proto`。`GatheringRequest` 包含版本、请求 ID、身体 ID，以及只读 `inspect`、单轮 `start` 或手动 `breath`。单轮启动传预期身体 revision、器官 ID、配方 ID/版本和连接 ID；手动输入传动作、归一化三维目标与严格递增序号。`aim_z` 省略时为入口平面 0.5，三个轴均校验有限且在 `[0,1]`。没有客户端指定的时间、来源、效率、命中或产出。

`GatheringView` 返回授权身体快照、环境浓度与供给预览、配方/目标组合，以及 `IDLE → INTAKING → REFINING → TRANSPORTING → COMPLETED` 阶段。执行失败进入 `FAILED`，保留原始 `FailureCode`。环境预览与目标余量都是读取事实，不预留库存、容量或共享供给预算。

选项来自实际器官的摄入能力、宿主允许的配方目录和器官直达经脉的有向连接；没有人体名称、数量或五行特例。同一组合列表遵守框架列表上限，超限时宿主应缩小本次公开目录。客户端按自己的资源包显示名称与模型。

## 自动吐纳契约

可信 `BreathingProfile.automatic` 提供停止耐力比例、接触采样效率和独立动作引用；框架不内置生物 ID。效率必须大于0且小于1，停止比例在 `(0,1]`；自动动作必须占用所声明的呼吸组织与全部呼吸器官，不能占用注意组织。缺少已声明动作属于配置错误。

`BreathControl.automatic` 只在 `BEGIN_BREATHING` 和 `SET_AUTOMATIC_BREATHING` 读取；返回 `BreathingView.automatic` 为权威模式。自动在实际空气边界切换吸呼，持续支付呼吸组织做功，不支付注意组织费用。低于配置停止线时，在本次费用提交后即停并解除占用。模式切换先结清旧区间再更换动作；不会免费补回预算。

`BreathingView.automatic_minimum_stamina_ratio` 与 `automatic_capture_efficiency` 是服务器从 `BreathingProfile.automatic` 投影的只读参数。客户端可用它们显示停止线和效率说明，但不能通过 `BreathControl` 覆盖；自动仍必须沿真实粒子接触、环境扣账、炼化和运输链结算。

自动沿同一气流、口鼻碰撞、真实环境原料扣账、炼化及运输链路；接触采样体积乘可信效率系数，客户端不能提交粒子命中或摄入证据。自动由服务器边界持续推进，关窗/断线须由宿主正式结束会话。手动仍使用750ms输入租约；自动不会因为不再按鼠标而失效。具体残卷授权和80%等人体数值归内容与宿主。

## 手动控制

宿主以可信生物内容的 `BreathingProfile` 调用 `enableBreathing`，绑定呼吸器官、空气容量 L、流速 L/s、呼吸组织、注意组织、功率 W 和允许的配方 ID。装配检查实际模块与已安装配方；具体人体初值属于 Human Addon。装配后单轮 `start` 拒绝，避免绕过主动引导。

`BEGIN_BREATHING` 结清此前闲置时间，`INHALE` / `EXHALE` 控制局部气流，`HOLD` 停气，`END_BREATHING` 结束。空气量受器官与所属部位的健康比例限制，达到上下界停止继续吸呼。每次按空气空间与两项组织实际能量预算截短有效时长；功率按当前爆发上限截断。未命中也消耗，两份成本沿唯一组织疲劳状态保存，重开不恢复。

活动时每 250 ms 安排事件，输入租约为 750 ms。客户端持续按键按 tick 续期；迟到序号拒绝，相同控制重放只读。失联停止，长暂停最多处理最近一个短区间，停气和换窗之前的旧时间先单独结清。闲置会话没有这些周期事件；逐帧渲染不调用身体算子。

框架已提供[按动作占用判断的指数恢复](Tissue-Recovery.md)。生物附属在 `BreathingProfile.body_action = 7` 绑定动作 ID/版本，由宿主装配可信动作目录。有正恢复半衰期的呼吸/注意组织必须配置绑定；定义须包含两项组织及全部呼吸器官。有效吸呼期间启动动作，停气、肺满、排空、结束和关闭时停止本实例。空闲呼吸事件会结算恢复，其他动作仍使用的组织不恢复。关窗本身不补满疲劳；重开按真实未结算空闲时间恢复，`IntakeQi.loads` 另排除本段做功组织。

占用启停与做功费用分别提交，动作本身不重复扣费。每次切换先结清旧状态；外部身体变更会中止原摄入计划，清理按最新快照只停止本会话实例。关闭须在撤销访问权前执行；清理失败必须由宿主重试或可信接管，不可遗弃仍占用组织的动作。

三维粒子最多 36 个，按真实环境库存中当前呼吸配置和单输入配方可处理的游离态属性配比抽样；没有可用原料时为空，失效粒子随来源变化清除。炼化损耗若回归为不支持的无属性真元，不会变成可再次吸收的彩色机会。入口为 `(0.5,0.4,0.5)`。三轴游离速率各不相同，基础速度为局部坐标 0.012–0.055/s；停气和肺满时仍移动，边缘折返保留身份。相机旋转只改变客户端观察，不改变服务端坐标。

空间使用连续三维源汇场近似空气流动：吸气沿径向向入口牵引，呼气向外推动，所有粒子都受影响。设粒子到入口距离为 `r`，其径向与瞄准方向夹角为 `θ`，方向权重为 `0.18 + 0.82 × max(0, cos θ)²`，距离权重为 `1 / (1 + r² / 0.22²)`；侧面和背面仍保留弱响应，近处及瞄准方向响应更强。

吸气、呼气场强与瞄准方向按 `1 - exp(-2.5 × 有效秒数)` 平滑接近当前输入；停气与肺容量边界使场强逐渐衰减，结束练习清除场强。径向加速度为 `(呼气场强 - 吸气场强) × 方向权重 × 距离权重 × min(0.4, 0.18 + 0.06 × 空气流速)`，在局部坐标内积分。粒子同时保留独立游走与惯性，速度上限为 0.24/s。该模型不是逐格流体求解，事件频率也不会叠加独立气流发射次数。

吸气期间，粒子进入三维入口半径 **0.08** 即可捕获；使用运动线段的最近距离检测，穿过入口也算命中。一次事件处理所有命中粒子，没有每 250 ms 一颗的数量上限，也不等待上一颗加工或到达。250 ms 仅保留为气流运动与做功的事件步长。二维投影重叠不能视为真实接触。

生物内容必须声明正数 `BreathingProfile.particle_volume_blocks`。接触摄入原始量为 `锁定来源当前总量 / 来源体积 × particle_volume_blocks`，粒子颜色选择原料属性。每颗提交前重读浓度与库存；同属性原料或器官缓存不足时只接收能保存的部分，完全无法接收则保留粒子。暂不按肺摄入速率、空气升数或经过时间缩放此剂量。空气上下限、健康与两项疲劳继续决定能否有效吸呼。

服务端命中后提交 `CaptureQi`，引用已安装的单种输入配方，按其输入输出比例即时转换。产物进入器官缓存，损耗原子回到同一环境来源。普通 `BodyCommandHandler.handle` 拒绝此命令，只有宿主完成权威接触检查后可调用 `handleCapturedQi`；客户端仍只提交方向。命中不消耗持续摄入的速率窗口，也不重置原窗口预算。固定批次的 `IntakeQi → StartOrganRecipe` 入口仍供其他用途。

每段有效吸呼先结算时间并通过 `ExertTissues` 支付一次两项成本，再逐颗接收，避免同段多颗重复收取疲劳。后续配送从真实器官缓存读取产物，通过既有通路发运；通路容量、吞吐和入向预约仍约束入脉，阻塞时保留缓存。`stored_qi` 仅在已跟踪货物实际到达后增加，缓存和在途不提前计入。会话重连从实际器官缓存继续配送，不重放粒子命中。

`BreathingView.failure` 也报告活动期间可恢复的摄入或配送阻塞，如缓存/目标已满、共享吞吐占用或来源不可用；是否仍在呼吸以 `active` 为准。空间和吞吐恢复后配送自动重试，反馈随下一次实际检查更新，不能把阻塞当作捕获成功或悄悄丢弃产物。开脉引导为等待输出的器官留出入口吞吐，见[开拓调度](Meridian-Opening.md)。

## 一轮如何执行

1. 检查身体、器官与所属部位、目标通路、原料和局部容量，容量扣除已有在途预约。
2. 结清启动前的时间，建立本轮起点；闲置或离线时间不能在按下按钮时变成免费摄入。起点恰好是身体已结算时刻且没有事件时，不创建空提交。
3. 按 `输入量 / min(器官摄入速度, 区域窗口供给速度)` 计算等待毫秒，向上取整。等待期间仅保留步骤，不预先领取真元。
4. 到期经 `BodyCommandHandler` 提交摄入，再启动权威目录中的配方。来源、共享预算、版本、权限与私有安全策略仍由每条命令检查。
5. 到加工完成边界结算真实产物，再按两端剩余共享吞吐沿所选连接发运。无空闲吞吐时将产物留在器官，等实际运输到达释放预约后再尝试。到达时结算，只有实际在途清除且身体存活才报告储存完成。

每条命令都有独立成功回执；身体、环境及在途仍只有原有账本。某一步失败不撤销已经完成的步骤，不自动重试、不凭空退款。由于启动可能已单独结算闲置时间，启动失败后应重新查询最新 revision。

同会话重放最近已接受的启动请求仅返回当前状态；同 ID 不同内容拒绝。更早的旧请求按旧 revision 拒绝。重新尝试必须先刷新快照，明确发起新一轮。没有持久化自动任务的隐含恢复：跨进程恢复使用身体、加工、在途和命令回执的既有保存规则，不重放 UI 的启动消息。

## Java 宿主职责

`GatheringSession<C>` 绑定可信上下文、身体 ID、`BodyCommandHandler`、快照读取与读权限策略、可信时钟、环境预览选择器和宿主允许的配方目录。该目录用于选项发现，不能代替每条命令的执行授权。预览选择器与摄入来源选择器须使用同一世界位置事实。

- 同一具身体同时只允许一个此类编排会话，宿主串行调度，替换会话前关闭旧会话。上下文使用稳定身份，权限策略每次读取当前授权。
- `handle(byte[])` 处理 Protobuf 请求；`view()` 只读，`nextBoundaryMillis()` 为零时没有待执行步骤，活跃吐纳返回下一次控制边界。
- 宿主在边界到期调用 `advance()`，变化后推送新的投影。一次调用内部使用同一个可信逻辑时刻。迟到会按实际可信时刻结算，不通过客户端时间补发资源；跨越不允许的来源窗口或其他事件会明确失败。
- 正常身体事件和寿尽调度仍由宿主负责。编排期间的外部身体变更会以版本冲突停止后续自动操作，已存在的加工和在途保留。它不是多任务调度器，也不会自动绕开伤势改道。
- 身体位置、权限、模式变化时及时通知编排或关闭会话；不能让离开的玩家继续消费旧地点的区间。环境选择器必须验证整个摄入区间。
- `close()` 停止后续步骤。关闭吐纳窗口发送 `END_BREATHING`，不必销毁宿主会话；已扣入的加工原料或在途仍由宿主推进，断线由宿主关闭会话。

提前调用 `advance()` 只检查条件，不调用身体算子；无需逐帧 apply。客户端进度条与模型脉冲只插值展示，不触发摄入与寿命更新。

普通时间结算的加工损耗仍进入默认 `environmentQi()` 释放账。宿主按位置回收时必须转移该账，不能在保留原账的同时再次给区域加元。参见[环境交换](Environment-Qi.md)。

宿主在同一串行调度中完成行走、恢复等合法身体更新后，可在下一次 `handle` / `advance` 前调用 `synchronizeBodyRevision()`。它接纳最新版本，后续步骤仍校验真实器官、货物与通路；没有调用时仍按原规则拒绝版本冲突。加工或到达已被其他时间事件结算时直接继续读取事实；同毫秒有到期资源或可执行自然扩散时仍结算，平衡无事件时不空提交。不得把这个方法作为客户端绕过冲突的入口。

相同吸呼方向的高频控制只更新瞄准与 750 ms 租约，气流仍按 250 ms 边界推进。改变方向、停止和容量边界会结清当前有效区间。多颗接触可以在同一模拟毫秒完成各自受校验的环境交换。

## 未开拓经脉

`QiTransport.start` 要求源经脉为 `OPENED`，否则返回 `MERIDIAN_UNOPENED`；这对所有生物和普通发运入口同样生效。目标经脉可以未开拓，因此固有器官可以先储存真元，再沿内容声明的[被动通路](Meridian-and-Qi.md)自然扩散。储存与扩散不改变开拓阶段、进度或境界。

[开脉任务](Meridian-Opening.md)拥有沿真实通路引导未开脉余额的专用权限。吐纳选项和实际运输共用扣除在途预约后的稳定体积余量，开脉期间同样不能超容。成功摄入才记录供给证据；吐纳负载与开脉连续费用累加到同一组织状态。

## 动画接线

UI 预览直接使用必装 Players-Animation 的打坐网格和独立播放器，肺与入口由生物展示资源的动画挂点定位，呼吸相位跟随实际空气量。Human Fabric 宿主按权威吐纳状态直接调用动画侧 `ServerPlayerAnimations.play/stop`，经动画自身的 Protobuf 同步外世界玩家。框架核心保持通用，不引用动画实现或复制动画协议。缺少必需通道或打坐资源时明确报错；客户端播放回执不参与资源授权。

## 验证范围

框架整体回归覆盖请求字段约束、未知字段拒绝，以及非人器官对第三方属性的完整摄入、炼化、未开拓经脉入账与守恒。Human 附属整体回归还覆盖手动吸呼、容量上下界、序号重放、租约失效、真实两项成本、原子摄入拒绝、资源耗尽和重开不补预算。UI 演示经真实 Screen 鼠标事件验证重复练习与环境续窗。
