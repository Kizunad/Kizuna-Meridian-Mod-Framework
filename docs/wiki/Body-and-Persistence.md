# 身体数据、寿命与持久化

**已确认：经脉模组拥有身体固有数据，寿命属于其中。** 不把年龄和寿命交给某个功法附属包单独记账。已实现模块数据、非致死寿元支出、可信时间与寿命推进、寿尽死亡及环境释放的内存原子事务参考，详见[基础数据定义](Data-Definitions.md)和[宿主接入](Host-Integration.md)。真实宿主的调度、实体死亡接入与磁盘持久化仍待实现。

## 所有权

附属持久进度使用身体 `addon_progress`，随同一 Protobuf 快照落盘。更新由可信 `SetAddonProgress` 原子提交并保留身体资源；普通客户端入口拒绝该操作。宿主在提交成功后标脏，重生按稳定身体身份恢复同一进度。框架不解释具体残卷或解锁 ID。

临时组织能力修正使用 `BodySnapshot.modifiers = 17` 随快照保存来源、起点、曲线与四项峰值，由可信活动原子增删。固定倍率使用两点常值曲线，起止允许阶跃。时间、做功、动作、运输、摄入、加工及其他身体状态变更保留尚未到期修正；`advance_time` 在活动模式按生效、拐点、到期分段结算并自动移除。`LIFESPAN_ONLY` 没有能力负载或恢复，可直接结算至目标或寿尽时刻，再按身体时钟移除到期项。寿尽、伤害致死或外部确认死亡均清空修正，`addon_progress` 仍保留。字段与校验见[组织能力修正](Data-Definitions.md#组织能力修正)。

| 状态 | 权威所有者 | 宿主与附属包如何使用 |
|---|---|---|
| 身体身份、实际构型、部位/组织/器官/经脉实例 | 经脉核心 | 宿主关联真实角色；附属包查询必要能力 |
| 伤势、疲劳、逐脉开拓阶段与进度、改造、成长、局部能力 | 经脉核心 | 已实现开拓数据随快照保存与恢复；伤害、恢复、开拓或改造通过各自受控请求推进 |
| 内腔、外壁、在途、器官缓存及加工原料 | 经脉核心唯一明细 | 宿主世界账本汇总对账，预计产物不提前记账 |
| 年龄、寿命上限、已耗寿元、寿命修正与生命状态 | 经脉核心 | 宿主给可信时间；功法/物品通过受控请求改变 |
| 已学定义引用、熟练记录、运行配置与必要执行进度 | 经脉核心 | 内容定义由附属包提供，记录不随包卸载删除 |
| 世界环境真元、库存、装备物品、权限与社会数据 | 宿主 | 向身体提供可信上下文，承担世界副作用 |
| 摄像机、选择、未提交的布局草稿 | 客户端 | 不影响权威身体或资源 |

伤害分配、连带损伤及生物特定致死条件由可信 Addon 通过[伤害接口](Health-Effects.md)裁定；未装配策略时使用可替换的随机部位直接扣血兜底。核心校验并保存唯一结果，自然寿尽由时间算子判定。宿主消费已提交结果完成实体死亡、掉落和世界事件。身体结算与外界副作用必须处于可恢复的提交边界，不能发一个无人消费的事件就宣称已经处理。

## 寿命的最小数据语义

以下概念分别表达；目前的 Java 字段与单位见基础数据定义，寿命修正来源尚待实现，时间推进规则见下节：

- **年龄**：真实经历的生物时间。以累计已结算时间为准，出生时间只作来源记录，不反复用当前系统时钟重新推算。
- **寿命承载上限**：基础构型的上限及已经生效的成长/改造修正。
- **已耗寿元**：功法等造成的额外寿元支出。它减少可用寿命，不将角色的实际年龄伪造成增长。
- **寿命修正来源**：来源 ID、实际变化、持续或永久属性、期限与提交操作 ID，便于审计和处理附属包缺失。
- **已结算时间游标**：时钟域/世代、时间位置和状态 revision，防止重连、重试或回档后重复结算同一时段。

当前关系为 `剩余寿命 = max(0, 有效寿命上限 − 已经历年龄 − 额外寿元支出)`，统一换算到同一生物时间单位。有效上限如何由物种、境界和修正计算仍由配置与规则明确；不在公共核心写死旧服务端的“一小时一年”。自然变老、延寿和燃烧寿元都必须走同一生命状态。

延寿、寿元支出与材料/真元费用一起提交。重复操作不能重复延寿；被拒绝的操作不消耗材料或寿命。通过阈值到达事件判定寿元耗尽，不每帧扫描全体生物；完成死亡处理后不重复触发。复活或创建新身体是否重建寿命须显式规则，不能默认填满。

当前 `LifespanSpending.apply` 仅实现无其他资源费用的非致死支出，输入为当前快照与正数生物秒，结果只增加已耗寿元和 revision。它是纯计算，不代表调用者已被授权或结果已提交；公开请求经 `BodyCommandHandler` 校验后才能写入。它不推进年龄、判定死亡或执行功法效果。致死支出、延寿与复合材料费用仍须后续实现。

## 已实现的时间与寿命推进

`BodyTimeAdvancement.apply(body, plan)` 以已结算游标为起点，用宿主给出的目标游标和固定倍率计算候选状态。`BodyCommandHandler` 的 `advance_time` 请求是空意图，时间事实由事务内的 `BodyTimeSource.resolve` 提供，不能来自客户端自报。跨进程事实使用 `TimeAdvancePlan` Protobuf 消息。

```text
经历的模拟秒 = (目标毫秒 − 已结算毫秒) / 1000
年龄增量 = 经历的模拟秒 × 每模拟秒对应的生物秒
```

年龄增加不改变已耗寿元或寿命上限；倍率为零时只推进模拟游标。每段区间内倍率和模式固定，宿主在切换在线/离线策略或倍率前，须先按旧策略结算至切换点，再使用新策略。框架不读取系统墙钟，不默认按现实离线时长老化。

| 边界 | 行为 |
|---|---|
| 同一时钟域、同一世代、目标更晚 | 只计算游标之后的区间；成功 revision 增加 1 |
| 不同时钟域或世代 | `CLOCK_MISMATCH`；宿主必须先显式迁移，框架不猜测时间对应关系 |
| 倒退，或同一游标且没有到达/阻塞状态变化 | `TIME_NOT_ADVANCED`；无写入、无新回执 |
| 同一请求成功后重试 | 返回原回执，不再读宿主时钟，不重复老化或释放 |
| `ACTIVE` | 按事件时间结算经脉/器官到达、配方完成和未被动作占用的组织疲劳恢复；组织端口到达仍以 `PENDING_TIME_EVENT` 拒绝整段 |
| `LIFESPAN_ONLY` | 伤势、疲劳、真元余额冻结；移动中到达和加工完成时刻随游标平移，已阻塞的历史时刻不变 |
| int64 平移溢出、年龄增量小到浮点无法记录 | `NUMERIC_LIMIT`；无写入，不能只移游标而漏掉年龄 |

恢复与年龄共用时间游标，具体单位、条件和接入方式见[组织耐力与精力恢复](Tissue-Recovery.md)。当前动作保存在 `BodySnapshot.actions`，启停前须按旧占用结清。恢复使用模拟秒和指数公式，与老化倍率独立；不另设逐帧恢复时钟。动作和完整占用定义随快照保存，冻结保留、死亡清空，缺包仍可停止；宿主按生命周期决定重连后继续或终止，见[动作规则](Actions.md)。

### 寿尽边界与死亡释放

`nextLifespanBoundary(body, rate)` 返回当前固定倍率下最早的寿尽模拟毫秒：`起点 + ceil(剩余生物秒 × 1000 / 倍率)`。边界取整使用十进制运算，已有死亡、零倍率且仍有余寿或超出 int64 时钟范围时无可调度边界。宿主在年龄、支出、上限或倍率变化后重算并安排唤醒；本库不启动逐帧扫描或后台线程。

推进目标达到或超过边界时，年龄只增加到寿尽，游标停在边界，`dead` 置为真。已经没有余寿但尚未标死的身体可以在原游标完成死亡判定。死亡后的新推进请求返回 `BODY_DEAD`。伤害致死另经可信 Addon 裁定，复用同一死亡清账；复活仍待实现。

`ACTIVE` 下按顺序处理死亡时刻之前的到达与加工完成；同毫秒死亡优先，其次加工完成，再次运输到达。死亡时经脉内腔/外壁、在途（含阻塞）、器官缓存和未完成加工输入各清账一次；原料不再额外生成预计产物。释放保留原有属性、数量与实际密度，加上该区间已完成加工产生的密度 `0.01` 无属性损耗，共同写入 `TimeAdvanceResult.released_qi`。组织端口等尚未实现的事件仍拒绝整段。环境后续退化、空间分布与表现尚未实现。

宿主可使用 `nextEventBoundary(body, rate, mode)` 安排最近的寿尽、能力修正生效/拐点/到期、移动中运输到达或运行中加工完成；冻结模式仍包含修正曲线边界。阻塞运输/加工等待相关状态变化后显式结算，不轮询；同毫秒恢复通路、器官或腾出容量后可以完成，年龄不重复增加。一次离线推进只遍历已经存在的事件，不循环模拟每个 tick，也不自动启动下一批配方。具体规则见[经脉与真元](Meridian-and-Qi.md)和[器官加工](Technique-Addons.md)。

能力修正的活动模式外层切段只选择严格晚于当前游标的曲线点，重合时刻共用一次结算；每段到达该边界或目标，寿尽则提前返回。一次推进期间不添加修正，因此外层迭代不超过输入曲线点数之和加一，32 条、每条 16 点时上界为 513，与经过时长无关；冻结模式只结算一次。整体回归使用固定种子 `20261026` 的 48 个随机满载身体，覆盖模式、开脉、寿尽和三种时钟范围的全部组合；每场景用 `Future.get` 限时两秒，JUnit 4 对整项测试限时 15 秒。整次推进与按输入拐点逐段推进的完整状态、死亡和资源释放对照，分段次数用于推断活动模式外层迭代数的上界。

内部切段使用只在当前调用内存在的 `BodyAdvancement` 候选和只读 `BodyView`，资源事件、疲劳、寿命和开脉仍依原顺序计算。组织、部位与曲线索引按需建立后复用；候选不会交给附属或宿主。事务结束才构造一个经过全量业务校验的 `BodySnapshot`，任何中途异常均丢弃整个候选。开脉策略继续逐次收到完整的不可变 Protobuf 视图，详见[同进程策略调用](Meridian-Opening.md#可信策略契约)。

`BodyTransactionStore.stage` 须将身体清账、死亡回执和环境入账一起提交。内存参考实现已实际增加 `environmentQi()` 账户，并验证回执与前后身体一致；提交前失败全部回滚，确认丢失后重试不重复发放。真实宿主须同时保存实体死亡等后续动作的可靠记录，不能通过可能丢失的审计回调执行这些动作。

年龄仍使用 `double`，分段计算按机器舍入，不承诺任意切分与一次推进逐位相同；相同输入和事件边界须遵循以上计算、向上取整和数值拒绝规则。阈值判断不靠反复扣减剩余寿命，也不把每帧显示插值写回账本。

## 保存职责

已有 `BodySnapshot` 与 `CommandReceipt` 的 Protobuf 编解码、`BodyTransactionStore` 原子提交接口及 `InMemoryBodyStore` 参考实现。时间回执还保存所采用的计划、实际游标、死亡标记与释放明细。恢复时一起加载已保存的环境余额，不能重放历史释放；内存适配提供三参数构造器接收该余额。编解码和内存适配不会写文件；正式保存后端仍需实现。保存目标为：

1. 核心产生完整、可校验的身体快照，包含身份、存档版本、模板/内容版本、revision、实例状态及时间游标。
2. Fabric 适配写入该世界的服务器存储；Bong 适配使用自己的持久化系统。客户端文件不能覆盖服务器存档。
3. 保存使用预期 revision 校验，身体变化、真元世界交换和消费结果由宿主事务或可恢复提交记录协调。具体技术不能由两个各自成功的写入替代原子性。
4. 加载时先校验版本、引用和所需能力，再实例化。坏数据或未知必要版本进入明确错误处理，不悄悄创建满血、满元的默认角色。
5. 缓存与汇总可重新派生，不作为另一份可修改余额。存档记录用于恢复，不再次执行“获得物品”“延寿”“已消耗”的副作用。

成功回执保存可信调用者、请求 ID、原命令与前后 revision，必须与身体一起原子提交、备份和恢复。它不同于只读审计日志，不能丢弃后假定客户端不会重试。当前同一身体生命周期内不设 TTL；不复用身体 ID 或倒退 revision。事务故障可能发生在确认返回前，调用者用原 ID 重试确定原结果。

内存参考 Store 恢复时逐条校验并建立按身体隔离的回执索引，不在每条记录后复制整个历史。运行期间只暂存当前新回执，在事务回调成功后于同一监视器内追加并发布身体与环境状态；回调失败不改变索引。对外仍返回不可变回执列表，保存格式及全部历史去重语义不变。

框架暴露存储接口，不限定 SQLite、NBT 或 Redis。基础模组必须交付可用的 Fabric 存储适配，不能只留接口而让单机无法保存。

## 离线与生命周期

| 场景 | 规则 |
|---|---|
| 重连 | 恢复同一身体与结算游标，不补满真元或修复伤势 |
| Bong 世界内退出 | 转入 NPC/离屏推进，仍用同一核心和同一份状态 |
| Bong 藏身处退出 | 只推进寿命，其余身体变化冻结 |
| 单机暂停/关闭 | 由公开宿主时间策略明确；默认建议随世界模拟暂停，不强制复制 Bong 的离线老化策略 |
| 死亡 | 内腔、外壁、在途、器官缓存和加工输入全部回环境，寿命与身体事件只结算一次 |
| 附属包缺失 | 保留已学引用、蓝图、实际改造和寿命变化；不能卸载一个包就退还已经付出的寿元 |

时间推进只接受宿主的可信事实。允许配置不同的单机时间节奏，但多人客户端不能提交“我离线多久”来决定年龄。各宿主必须明确离线时钟与恢复政策，并验证跨时钟世代不会重复老化。
