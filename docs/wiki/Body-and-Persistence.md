# 身体数据、寿命与持久化

**已确认：经脉模组拥有身体固有数据，寿命属于其中。** 不把年龄和寿命交给某个功法附属包单独记账。首片已实现模板/实际构型分离、逐模块状态、真元明细、寿命与结算游标，详见[基础数据定义](Data-Definitions.md)。持久化后端及时间推进仍未实现。

## 所有权

| 状态 | 权威所有者 | 宿主与附属包如何使用 |
|---|---|---|
| 身体身份、实际构型、部位/组织/器官/经脉实例 | 经脉核心 | 宿主关联真实角色；附属包查询必要能力 |
| 伤势、疲劳、改造、成长、局部能力 | 经脉核心 | 提交伤害、恢复或改造请求，由核心验证 |
| 内腔、外壁、在途真元 | 经脉核心唯一明细 | 宿主世界账本汇总对账，不另存可支出余额 |
| 年龄、寿命上限、已耗寿元、寿命修正与生命状态 | 经脉核心 | 宿主给可信时间；功法/物品通过受控请求改变 |
| 已学定义引用、熟练记录、运行配置与必要执行进度 | 经脉核心 | 内容定义由附属包提供，记录不随包卸载删除 |
| 世界环境真元、库存、装备物品、权限与社会数据 | 宿主 | 向身体提供可信上下文，承担世界副作用 |
| 摄像机、选择、未提交的布局草稿 | 客户端 | 不影响权威身体或资源 |

伤势、寿元不足等导致的身体失能/死亡由核心给出结果，宿主消费唯一结果完成实体死亡、掉落和世界事件。身体结算与外界副作用必须处于可恢复的提交边界，不能发一个无人消费的事件就宣称已经处理。

## 寿命的最小数据语义

以下概念分别表达；目前的 Java 字段与单位见基础数据定义，寿命修正来源与推进规则尚待实现：

- **年龄**：真实经历的生物时间。以累计已结算时间为准，出生时间只作来源记录，不反复用当前系统时钟重新推算。
- **寿命承载上限**：基础构型的上限及已经生效的成长/改造修正。
- **已耗寿元**：功法等造成的额外寿元支出。它减少可用寿命，不将角色的实际年龄伪造成增长。
- **寿命修正来源**：来源 ID、实际变化、持续或永久属性、期限与提交操作 ID，便于审计和处理附属包缺失。
- **已结算时间游标**：时钟域/世代、时间位置和状态 revision，防止重连、重试或回档后重复结算同一时段。

候选展示关系为 `剩余寿命 = max(0, 有效寿命上限 − 已经历年龄 − 额外寿元支出)`，统一换算到同一生物时间单位。有效上限如何由物种、境界和修正计算仍由配置与规则明确；不在公共核心写死旧服务端的“一小时一年”。自然变老、延寿和燃烧寿元都必须走同一生命状态。

延寿、寿元支出与材料/真元费用一起提交。重复操作不能重复延寿；被拒绝的操作不消耗材料或寿命。通过阈值到达事件判定寿元耗尽，不每帧扫描全体生物；完成死亡处理后不重复触发。复活或创建新身体是否重建寿命须显式规则，不能默认填满。

## 保存职责

已有 `BodySnapshot` 数据类型、结构校验及 `BodyProtobuf.encodeSnapshot/decodeSnapshot` 二进制编解码；格式由 `.proto` 与 protoc 生成类型定义。编解码不会写文件或推进时间，`BodyRepository` 与实际保存操作仍是候选契约。保存目标为：

1. 核心产生完整、可校验的身体快照，包含身份、存档版本、模板/内容版本、revision、实例状态及时间游标。
2. Fabric 适配写入该世界的服务器存储；Bong 适配使用自己的持久化系统。客户端文件不能覆盖服务器存档。
3. 保存使用预期 revision 校验，身体变化、真元世界交换和消费结果由宿主事务或可恢复提交记录协调。具体技术不能由两个各自成功的写入替代原子性。
4. 加载时先校验版本、引用和所需能力，再实例化。坏数据或未知必要版本进入明确错误处理，不悄悄创建满血、满元的默认角色。
5. 缓存与汇总可重新派生，不作为另一份可修改余额。存档记录用于恢复，不再次执行“获得物品”“延寿”“已消耗”的副作用。

框架暴露存储接口，不限定 SQLite、NBT 或 Redis。基础模组必须交付可用的 Fabric 存储适配，不能只留接口而让单机无法保存。

## 离线与生命周期

| 场景 | 规则 |
|---|---|
| 重连 | 恢复同一身体与结算游标，不补满真元或修复伤势 |
| Bong 世界内退出 | 转入 NPC/离屏推进，仍用同一核心和同一份状态 |
| Bong 藏身处退出 | 只推进寿命，其余身体变化冻结 |
| 单机暂停/关闭 | 由公开宿主时间策略明确；默认建议随世界模拟暂停，不强制复制 Bong 的离线老化策略 |
| 死亡 | 内腔、外壁及在途真元通过合法账户回环境，寿命与身体事件只结算一次 |
| 附属包缺失 | 保留已学引用、蓝图、实际改造和寿命变化；不能卸载一个包就退还已经付出的寿元 |

时间推进只接受宿主的可信事实。允许配置不同的单机时间节奏，但多人客户端不能提交“我离线多久”来决定年龄。各宿主必须明确离线时钟与恢复政策，并验证跨时钟世代不会重复老化。
