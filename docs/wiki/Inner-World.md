# 内景与经脉操作

状态：3D 工厂交互为目标玩法，尚未实现。既有二维网页只是讨论原型，不是游戏引擎或 3D 成品。

## 基本操作

- 玩家进入内景配置身体运行，外界仍只有一个真实实体，继续受环境和攻击影响。
- 经脉展开为长方形区域，上下端口表示跨经脉输入与输出；完成该脉开拓后开放主动取用与线路运行，保留经典连续拉传送带操作。
- 传送带由精力/意念形成，货物是各属性的真元。精力与真元是不同资源，实际输送和配方激发都需计成本。
- 器官和肌肉表现为可配置多方块，右键通过 XML/owo 窗口选择已学配方、设置允许参数。
- 移动投影只是整理布局，不免费移植器官；显示格数不代替真实经脉距离与控制延迟。
- 每条经脉保留独立容量、外壁储备、吞吐与损伤，不因进入内景而合成一个大真元池。

推荐一个连续主内景，内部保留多个经脉内腔，方便观察全身线路；单空间或多房间仍未最终定案。无论画面怎样分区，运行始终引用同一身体实例。

## 局部资源与引元口

已确认的交互方向：每条经脉内腔是有限、可补充的局部资源区，通过意念形成的“引元口”把当地真元送上传送带。第一版每脉提供一个固定引元口，只有完成该脉开拓后才可启用。引元口从该脉内腔取料，上下跨脉端口负责与其他经脉连接，两者职责不同。

内腔按储量、属性和相态显示光点、气雾、液流或晶质流动，货物以批次表现。内壁深处的纹理显示长期外壁储备；储备须先动员到内腔才能主动取用。资源显示读取同一身体账本，画面上的粒子和设施不额外持有余额。

引元口配置取用属性与相态、请求流量、本次数量或持续供给，以及本脉保留量。实际供给同时受余额、吞吐、通路、精力和控制能力约束。即使后续允许多个引元口，也共享本脉的余额与吞吐；改变内景显示位置不改变真实取用范围和输送距离。

真元补充来自经过验证的环境摄入与转化、外壁动员或沿线路返回的可回收余量。引元口只提取已有真元。肺、胃或其他生物的特异器官通过各自能力提供摄入与加工，基础框架不写死器官名称。

建议将起步体验表达为：看见尚未响应意念的经脉 → 通过入门聚灵过程开拓首脉 → 引元口亮起并可用 → 从引元口拉带 → 连接器官或肌肉设施 → 选择配方并启动。未开拓区域可以展示构型与开拓条件，主动线路须等对应经脉开拓后才能运行。[首脉起步规则](Meridian-and-Qi.md)区分已确认方向与待细化的聚灵方案。

本节为待实现设计；当前账本和单批次运输提供基础，开拓门槛、引元口、外壁动员、精力费用和持续供给仍需接入运行核心。

## 编辑和执行分开

保存布局、绑定配方与激发动作是不同操作。保存不会自动发动攻击；配方激发必须在当前身体、知识、武器、资源条件下重新校验。

首个切片聚焦胸部到一侧上肢、一处肌肉设施、直带/弯带、配方选择、一次动作和受伤退出。分流器、复杂电路、子蓝图、多任务调度是后续扩展，不阻塞最小切片。

失败显示所在阶段、组织/通路、具体原因、已发生的资源变化与调整入口。例如局部储量不足、通路堵塞、未学配方、武器不符、精力不足。失败不回滚已经真实完成的运输。

## 工厂运行优先级

下一步优先补齐工厂运行核心：根据实际连接、已开拓范围、引元口配置与器官配方，计算真元去向、属性、数量、到达时间和阻塞原因。上游到达可触发下游加工，加工完成可触发下一段运输；终端按配方留存、回流或利用真元。保存布局与主动动作激发仍各自校验。

首个运行切片聚焦“已开拓经脉取料 → 单路运输 → 器官加工 → 下游接收”，再接组织利用与肌肉效果。首脉未开时单独验证聚灵开拓入口，避免要求玩家先使用尚未解锁的取料设施。循环线路按事件持续推进，预览明确给出模拟时长或执行次数。

## 受伤退出与性能

受伤后由服务端撤销编辑会话，通知客户端释放镜头与输入；迟到编辑请求不能生效。已发生的资源和已生效增益保留，未执行主动请求如何终止由统一状态机处理。

关闭内景不等于停止身体运行。服务端只维护逻辑图和事件，不要求无人观看时加载 3D 房间或让每个显示方块 tick。客户端按已知时间和路线插值真元批次，不驱动账本。

3D 渲染、选块和镜头需要专门实现；XML/owo 负责配置面板，不宣称它自带 3D 工厂编辑器。
