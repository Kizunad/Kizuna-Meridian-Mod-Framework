## 实施前需要冻结的技术事项

产品方向已经形成基线，不重复询问是否拆仓或是否允许附属包。剩余主要是可执行合同：

1. 身体实例与连接清单、逐脉开拓门槛与首脉聚灵入口、时间和数量单位、压差/吞吐/损伤与成长算子。
2. 寿命数据、时间游标、保存版本和宿主原子提交方式。
3. 公开 API、线协议、扩展清单及首版支持平台。
4. 简易入口的来源/目标选择、路线预览与执行反馈；单一主内景或多个内腔的空间表达留在 3D Addon 切片确定。
5. 新人体数值、突破稳定时长/材料和具体动作配方的验算。

这些事项在相应切片进入生产前冻结，不应为了仓库初始化伪造空壳接口和通过的测试。

## 首个可验证切片

查询首片已实现：Protobuf 请求 → 宿主提供可信身份与读取权限 → 查询权威身体 → Protobuf 响应。Java 工程提供参考处理器，已使用独立 Python 客户端完成一次性通信验证，临时验证文件已清理；不要求 Rust/JNI，也不把查询通过等同于运输、配方或持久化已实现。

变更首片已实现授权、版本与资源校验、私有策略、原子提交和去重。时间切片已接入宿主可信计划、年龄推进、寿尽与冻结；运输支持共享吞吐、容量预留、扣源/在途/到达和阻塞恢复。第 4 项已提供组织力量/功率/耐力、能力查询与做功，以及器官缓存、protoc 配方目录、加工中原料、按时完成和环境损耗。

逐脉开拓数据与[运行](Meridian-Opening.md)已实现：规则登记、开始/暂停、任务存档、沿图引导、临时增压、真实摄入窗口、持续费用、适应计时、完成一次扩容与中止释放。普通运输仍限制未开拓源脉主动出元，专用引导使用受控权限和同一在途账本。

[环境真元交换契约](Environment-Qi.md)已实现供给、交换与回执的 protoc 消息和 Java 有界校验，覆盖来源/版本、有效区间、额度、速率与双向明细。[环境配置](Environment-Configuration.md)已支持 TOML、chunk 区域、浓度挂钩供给和方块传播系数。库存预算与原子交换已有参考实现，实际世界来源选择、磁盘持久化及扩散调度仍待接入。

环境优化已提供背景区域、局部房间、通道段的 Protobuf 定义，以及只在变化时更新的分片边界缓存。已取消方块变化监听、世界扫描及修炼室自动识别。[地形随机生成](Terrain-Qi-Generation.md)已有主世界 TOML 表、五行偏好、未分类群系规则、稳定生成候选与共享边界倍率；房间/通道按生成结果或内容定义登记。缓存支持增量替换、版本拒绝、失效暂停与保存恢复。[通用器官摄入](Environment-Qi.md)已接通区域库存、共享窗口预算、身体缓存/时间与回执的原子交换，并供开脉验证持续摄入。动态按属性炼化与区域扩散调度仍待实现；人体附属配置肺的能力与参数，主框架不设置人体默认值。重载区域必须恢复现存库存、预算与倍率。

后续推进[工厂运行核心](Inner-World.md)：动态炼化、引元口供给、通用单路自动运输、器官自动加工、下游接收与诊断，再接组织真元利用、肌肉增益和动作输出。首脉专用引导已独立于普通主动取料执行；开脉自动路由不等于通用工厂任务调度已经完成。

本轮通用经脉被动扩散已完成，Human 配置肺经入口与全身连接；它与尚未执行的世界区域间扩散是两套空间尺度不同的流程。未开脉可自然储元，沿实际连接按占比差发运，与主动运输共用吞吐和唯一账本。整体回归覆盖循环、异构容量、保存恢复、分段一致、阻塞、冻结、寿尽及摄入共存。

Human 已登记[开脉配置](Meridian-Opening.md)，按境界解锁经脉并配置启动储量、持续摄入、脑耐力与精力消耗、增压门槛和递增维持时间；具体数值以附属的[修炼要求](https://github.com/Kizunad/Kizuna-Meridian-Human-Addon/wiki/Cultivation)为准。协议、执行与人体命令已接通；仍需 Windows 实机验收、长期节奏平衡及境界相变突破。

[动作占用](Actions.md)现已独立接入：附属注册组织/器官使用声明，核心保存并行动作并按占用并集计算指数恢复。Human 已登记行走、跑步和吐纳，提供恢复半衰期；吐纳编排已启停占用，实际 Minecraft 行走/跑步检测和持续负载仍由宿主接入。

运行核心完成后，安装独立人体附属模组与基础功法包，通过简易操作入口在 Fabric 内置服务端和 Bong 中分别验证：聚灵开拓首脉 → 选择来源、目标与配方 → 预览并执行取料、运输与加工 → 对应肌肉蓄力 → 执行拳击 → 回归环境 → 保存重开。随后 3D Addon 接入相同逻辑线路与规则，另验铺带和受伤退出。真实学习来源、损伤/恢复及环境/实体动作仍需补齐核心及宿主事务能力。

基础模组不安装人体或功法包时也能加载；已由有效定义创建的身体按其现有状态运行。官方人体包、基础功法包与其他独立包都通过公共接口接入，核心不设置物种或流派白名单。

## 必要验收

- 人体包与非人构型使用同一公开契约和算子；摄入、炼化与生命条件按声明能力执行，主框架不存在人体名称/ID 特判或默认人体兜底。人体内容缺失时按实际依赖处理，不重置现有身体。
- 首脉未开时可进入聚灵开拓过程，但不能主动取用其储量；开拓成功只开放对应经脉，其他经脉仍保持原状态，资源不凭空补满。
- 工厂依实际连接自动推动运输与加工；缺料、满载、未开拓或通路失能有可定位的原因，循环按事件推进且无零时间无限执行。
- 内腔/外壁/在途/器官缓存及加工输入与环境守恒；容量增加不产生真元，预计产物不重复记账。
- 寿命推进一次；重试不重复延寿或燃烧寿元；重连不复原伤势。
- 权限/会话/资源/版本不符无副作用；私有安全策略拒绝同样如此。
- 缺包保留引用与实际身体；多包共享资源和局部增益约束。
- 不安装 3D Addon 可完成基础操作闭环；对同一身体提交同一逻辑配置与执行请求时，简易入口与 3D 入口获得相同资源、时序和效果结果。
- 客户端退出不停止服务端运行；3D 内景受伤撤销编辑且拒绝迟到请求。移除纯交互 Addon 后，已提交逻辑配置仍可由基础入口查看和控制。
- 不同服务端实现通过共同协议与行为验收；选择原生桥接的部署另验声明平台实际装载。无 Bong、无私有插件的单机完成真实游玩与保存重开。

测试保护外部结果、守恒、原子性、持久化和协议，不以数量或私有字段覆盖率作为完成标准。
