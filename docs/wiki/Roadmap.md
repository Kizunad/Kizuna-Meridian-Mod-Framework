## 实施前需要冻结的技术事项

产品方向已经形成基线，不重复询问是否拆仓或是否允许附属包。剩余主要是可执行合同：

1. 身体实例与连接清单、逐脉开拓门槛与首脉聚灵入口、时间和数量单位、压差/吞吐/损伤与成长算子。
2. 寿命数据、时间游标、保存版本和宿主原子提交方式。
3. 公开 API、线协议、扩展清单及首版支持平台。
4. 单一主内景与多个内腔的最终空间表达；首片先验证一侧上肢。
5. 新人体数值、突破稳定时长/材料和具体动作配方的验算。

这些事项在相应切片进入生产前冻结，不应为了仓库初始化伪造空壳接口和通过的测试。

## 首个可验证切片

查询首片已实现：Protobuf 请求 → 宿主提供可信身份与读取权限 → 查询权威身体 → Protobuf 响应。Java 工程提供参考处理器，已使用独立 Python 客户端完成一次性通信验证，临时验证文件已清理；不要求 Rust/JNI，也不把查询通过等同于运输、配方或持久化已实现。

变更首片已实现授权、版本与资源校验、私有策略、原子提交和去重。时间切片已接入宿主可信计划、年龄推进、寿尽与冻结；运输支持共享吞吐、容量预留、扣源/在途/到达和阻塞恢复。第 4 项已提供组织力量/功率/耐力、能力查询与做功，以及器官缓存、protoc 配方目录、加工中原料、按时完成和环境损耗。

逐脉开拓数据已实现：`MeridianState.opening` 保存阶段与进度，身体 schema 2 要求显式提供；运输和死亡清账保留该事实，协议往返与非法输入已有整体回归。当前尚无开拓任务、进度推进或调用门槛。

[环境真元交换契约](Environment-Qi.md)已实现供给、交换与回执的 protoc 消息和 Java 有界校验，覆盖来源/版本、有效区间、额度、速率与双向明细。[环境配置](Environment-Configuration.md)已支持 TOML、chunk 区域、浓度挂钩供给和方块传播系数；实际环境选择、库存预算、扩散调度和交换原子事务仍待接入，之后再使用该契约推进聚灵。

下一步优先实现[工厂运行核心](Inner-World.md)：开拓调用校验与首脉聚灵 → 引元口供给 → 单路自动运输 → 器官自动加工 → 下游接收与诊断，再接组织真元利用、肌肉增益和动作输出。首脉尚未开拓时，要有独立于主动取料设施的聚灵开拓入口。开拓剂量、时间、失败规则与环境摄入仍需细化；现有算子没有开拓校验，不能把这一设计视为已实现。

运行核心完成后，用一套人体状态在 Fabric 内置服务端和 Bong 中分别验证：聚灵开拓首脉 → 按布局取料、运输与加工 → 对应肌肉蓄力 → 执行拳击 → 回归环境 → 保存重开。内景 3D 建造、受伤退出与真实学习来源接入同一运行规则；损伤/恢复和真实环境/实体动作仍需补齐核心及宿主事务能力。

基础模组不安装功法包时也能加载并维持身体。官方基础包与第二个独立包都通过公共接口接入，不修改核心的流派清单。

## 必要验收

- 首脉未开时可进入聚灵开拓过程，但不能主动取用其储量；开拓成功只开放对应经脉，其他经脉仍保持原状态，资源不凭空补满。
- 工厂依实际连接自动推动运输与加工；缺料、满载、未开拓或通路失能有可定位的原因，循环按事件推进且无零时间无限执行。
- 内腔/外壁/在途/器官缓存及加工输入与环境守恒；容量增加不产生真元，预计产物不重复记账。
- 寿命推进一次；重试不重复延寿或燃烧寿元；重连不复原伤势。
- 权限/会话/资源/版本不符无副作用；私有安全策略拒绝同样如此。
- 缺包保留引用与实际身体；多包共享资源和局部增益约束。
- 客户端退出不停止服务端运行；受伤撤销编辑且拒绝迟到请求。
- 不同服务端实现通过共同协议与行为验收；选择原生桥接的部署另验声明平台实际装载。无 Bong、无私有插件的单机完成真实游玩与保存重开。

测试保护外部结果、守恒、原子性、持久化和协议，不以数量或私有字段覆盖率作为完成标准。
