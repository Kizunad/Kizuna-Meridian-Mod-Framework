# 地形灵气生成与肺的炼化

状态：主世界地形默认配置、Protobuf 生成契约和 `TerrainQiGenerator` 确定性生成已实现，可生成初始库存候选与共享边界快照。[区域库存与器官摄入原子事务](Environment-Qi.md)已有内存参考；实际世界生成回调、磁盘存档与扩散提交仍待接入。肺的转换方向已确认，下方效率和成长数值为首轮建议，尚未装配为人体内容或器官改造算子。

## 主世界默认地形表

浓度单位为元/格，格指一个方块体积。权重按金、木、水、火、土排列，默认合计 100，因此可读作扰动前的百分比；它描述环境成分，不是器官吸收率。所有初始灵气使用游离态，各属性共同分配一份区域总量。

| 稀树草原、风袭草原、疏林恶地 | 0.45–0.85 | 10 | 40 | 10 | 15 | 25 | 木，次土 |

这些是玩法数值，不以真实植物密度实时计算。生成时每项权重乘以 `[0.8, 1.2)` 的独立随机因子，再归一化，保留地形的大方向，同时让同类区域略有差别。偏好不是某属性是否允许出现的门槛，五行均有正份额。当前默认不生成天然无属性灵气，后续身体释放仍可使环境拥有无属性真元。

已分类区域在表中区间内均匀抽取浓度；数量为 `浓度 × 实际体积`。表只控制首次初始分布，后续扩散与吸收会改变各区域浓度及成分，不能一直用地形表覆盖实际库存。当前扩散规则会逐渐抹平差异，维持长期灵地需要另行定义守恒的供给来源，本轮没有隐藏的自动补满。

## 未分类与第三方地形

只按完整群系 ID 精确匹配 TOML 中的 `biomes`。没有匹配项时，包括其他模组群系，采用以下规则：

1. 根据世界种子、维度和群系 ID，在默认总范围 `[0.20, 1.60]` 内独立抽两个值，排序为该群系的专属浓度区间。
2. 对金、木、水、火、土各抽一个 `[1, 100)` 权重，形成该世界中此群系的稳定基础偏好。先抽权重再归一化，五个百分比不会各自随机后超出总量。
3. 各区域再用自己的来源 ID 在此区间内抽浓度，并应用与已分类地形相同的权重扰动。

同一世界的同一未知群系共享基础区间和偏好，不会每个区块重新变成另一类地形。不同世界种子可以不同。模组作者或服主可把群系 ID 明确加入某个预设，或新增完整预设。名称包含 forest 并不自动被猜测为森林。

## 配置与生成入口

默认数据位于服务端资源 `meridian-environment.toml`。`EnvironmentQiConfig` 升为配置版本 2，新增 `generation = 7`；线协议仍为 v1，身体 schema 仍为 2。

```toml
[generation]
rules_version = 1
dimension_id = "minecraft:overworld"
unclassified_min = 0.20
unclassified_max = 1.60
boundary_min = 0.25
boundary_max = 1.00
preference_jitter = 0.20

[generation.profiles."addon:crystal_woods"]
biomes = ["addon:crystal_forest"]
concentration_min = 1.20
concentration_max = 2.00
# 金、木、水、火、土，正权重；无需合计恰好为 100。
weights = [25, 50, 10, 5, 10]
```

预设按 ID 覆盖，已有预设的省略字段沿用默认值；`biomes` 与 `weights` 数组整体替换，空 `biomes` 可停用映射。新增预设必须提供区间两端和完整五行权重。一个群系只能属于一个预设，重复映射拒绝安装；重新归类时先从旧预设列表移除。所有未知键、无效 ID、反向区间、负数或无穷、非五项权重、非正权重均拒绝。

| 契约或 Java 入口 | 用途 |
|---|---|
| `TerrainQiGenerationConfig` | 算法版本、维度、未知地形总范围、边界倍率范围、扰动和地形预设 |
| `TerrainQiRegionRequest` | 世界种子文本、维度、唯一来源 ID、群系 ID、实际体积与协议版本 |
| `TerrainQiRegionSeed` | 输入依据、算法版本、采用区间、实际权重与初始五行库存候选 |
| `TerrainQiBoundaryRequest` | 世界种子、维度、边界 ID、两个来源 ID、接触面积与规则世代 |
| `TerrainQiProtobuf` | 区域/边界请求和生成记录的有界编解码、配置与内容校验 |
| `new TerrainQiGenerator(config.getGeneration())` | 安装并索引可信配置 |
| `generateRegion(request)` | 纯计算一个区域的初始候选，不读取或写入世界 |
| `generateBoundary(request)` | 生成只有一个 `generated` 分片的就绪边界快照，可直接交给 `EnvironmentBoundaryCache` |

请求和结果属于宿主内部契约，不能注册为客户端生成资源的命令。配置拒绝不同维度请求；要生成其他维度，宿主须显式安装对应维度配置。体积必须为正；零浓度配置可产生空库存，正数下溢、数量溢出或无法有效表示五行分配时拒绝候选。

边界倍率默认在 `[0.25, 1.00)` 内均匀抽取，可配置为 0 或大于 1；相等端点表示固定倍率。交换两个来源输入顺序产生同一份结果。面积由区域尺寸与有效高度算出，不查询方块。倍率不是固定元/秒，仍使用[浓度差与候选流量](Environment-Configuration.md)规则。

## 宿主生成与保存

服务端创建世界、首次生成区域时，从已有地形生成元数据取得群系，不扫描方块。建议每个 chunk 使用生成阶段的代表地形；当环境区域为 N×N chunk 时，对这些 chunk 的代表群系计数，选择占比最大的群系，平票按群系 ID 的 UTF-8 字节序选择。代表地形的取样点须由宿主固定，优先地表元数据，避免整列区域因洞穴群系取样而随机切换。

生成器只接受宿主最终确定的一个 `biome_id`，不负责代表地形选取。多 chunk 区域要等全部所需元数据确定或由世界生成器直接查询齐全后再初始化，不能依赖哪一个 chunk 先加载来定值。需要洞穴独立环境时，由内容显式登记空间与体积。

宿主以来源唯一键执行“尚不存在才初始化”，一起保存生成依据、规则配置修订、空间与当前库存；并发生成同一来源只能有一个结果入账。再次加载恢复当前库存，不把 `initial_qi` 重放为发放指令。修改 TOML 只影响新初始化区域；已有区域与边界更新须走显式版本与事务路径，不能重新抽样覆盖余额。生成候选本身无法保证这一持久化行为。

## 可复现算法

`rules_version = 1` 使用 SHA-256。每个字符串以“4 字节大端 UTF-8 字节长度 + UTF-8 内容”依次输入哈希，前缀为 `kizuna:terrain-qi`、十进制算法版本、用途标签，再附对应身份字段。摘要前 8 字节按无符号大端解释、右移 11 位取得 53 位整数，乘 `2^-53` 得到 `[0,1)` 均匀值。区间插值为 `min + (max - min) × u`，浮点使用 binary64，运算顺序与参考实现相同。

| 用途标签 | 前缀之后的身份字段 |
|---|---|
| `unknown-range-a` / `unknown-range-b` | 世界种子、维度、群系 ID |
| `unknown-weight:<属性 ID>` | 世界种子、维度、群系 ID |
| `region-concentration` / `region-weight:<属性 ID>` | 世界种子、维度、群系 ID、来源 ID |
| `boundary-transmission` | 世界种子、维度、按 UTF-8 无符号字节序排序的两个来源 ID |

每个用途单独哈希，不使用共享随机数游标。五行顺序固定为金木水火土；先分配前四项，末项接收总量减去前四项的余量。世界种子按稳定文本提供，Minecraft long 种子建议用无多余前导零的十进制字符串，保留负号。相同有效配置和身份产生相同输出，配置列表重排、边界两端加载顺序不影响结果。

已通过独立 Python 算法核对的向量：种子 `-42`、维度 `minecraft:overworld`、群系 `minecraft:desert`、来源 `region/-1/0`，`region-concentration` 得到 `u=0.6280998518198633`；默认沙漠浓度为 `0.22561997036397266` 元/格。完整宿主跨语言生成接入仍须自行验收。

## 人体附属模组的肺炼化配置

本节记录人体附属模组的内容方向与平衡参照，不是主框架的默认器官配置。主框架已有通用原始摄入与守恒事务，动态按属性炼化仍待补齐；人体包通过同一公开契约配置肺，其他生物包配置各自器官。

已确认：初始人体肺对金、木、水、火、土采用相同固定效率，产出无属性真元；器官改造可以单独提高某种属性的炼化效率。环境某种属性含量较高，不自动赋予游炁角色该属性的攻击能力。

首轮建议五行效率均为 **20%**，待实际恢复节奏校准。它由人体附属模组提供，不进入主框架默认资源、全局环境配置或通用经脉构造器。其他生物由自身摄入器官声明同类能力，框架不检查是否名叫“肺”。需要记录的后续器官参数为“输入属性 → 有效转换率”，取值 `[0,1]`；实际实例改造后的参数由权威身体状态保存，人体包与功法包都不能另存可写副本。

```text
某属性炼化所得 = 实际摄入的该属性元数 × 该器官对此属性的转换率
无属性产出 = 各属性炼化所得之和
未利用量 = 总实际摄入 - 无属性产出
```

未被摄入的灵气始终留在环境；已进入器官但未利用的部分按加工损耗返回环境，不能当作消失，也不能留在身体再退还一次。沿用当前器官加工损耗的无属性游离态回流规则。首境产出为无属性游离态真元；后续相态受独立承载与相变规则控制，吸收效率高不代表自动获得高阶相态。

例如森林按基准配比摄入 10 元，其中木 6 元：所有效率 20% 时得到 2 元无属性真元；只将木效率改为 40%，则得到 `6×40% + 4×20% = 3.2` 元，剩余 6.8 元回归环境。器官吞吐、共享环境供给、目标容量仍限制每秒实际摄入量，提高转换率不会绕过这些限制。

按默认采集速度 1 格/秒、初始效率 20%、游炁可用内腔 20 元粗略估算：沙漠浓度中点恢复约 500 秒，平原约 125 秒，森林约 71 秒，丛林约 51 秒。这仅是假设浓度稳定且没有器官吞吐等其他瓶颈的平衡参照，不是当前已经可玩的恢复时间。

选择性吸收的优化提高的是对应输入的利用率，不把其他四项自动归一化降低。环境偏好、器官转换效率、后续无属性真元转五行力量的配方效率是三个独立参数；真炁附效、化元创造的阶段限制继续适用。
