# Fabric 单机与 Bong 接入

状态：目标环境已确定，适配与桥接尚未实现。

目前已提供宿主无关的 [Protobuf v1 数据与查询契约](Protocol-and-Security.md)。Java 消息由 protoc 生成；其他语言使用同一 `.proto` 或构建描述集生成类型。Java 编解码可运行，但网络通道、查询处理器、Rust 生成工程及 JNI 仍未接入，不能将格式可解码等同于身份授权或身体操作已经执行。

## 一套权威核心

推荐由 Rust 库提供身体计算与数据模型。Fabric 的内置服务端通过薄 JNI 桥接调用，Bong 在 Rust 进程内直接调用。客户端只渲染快照并发出意图。

| 环境 | 正式状态在哪里 | 宿主承担 |
|---|---|---|
| Fabric 单机 | 内置服务端持有的身体核心实例 | 世界时间、实体/装备映射、环境真元、命中/增益、书籍学习和世界存储 |
| Fabric 专用服务器（扩展目标） | 专用服务器实例 | 复用单机服务端契约，不加载客户端 UI 类 |
| Bong | Bong 服务进程持有的同一核心类型 | 身份权限、既有世界账本、战斗/移动/库存消费者、数据库、NPC/离屏推进 |

连接 Bong 时，客户端不能同时运行另一份本地权威身体。Bong 不需要安装 Fabric JAR；其接入产物为 Rust 核心与固定版本的协议/内容包。

## 数据输入与世界输出

宿主提供可信时间、身体身份、实际装备/学习事实、环境供给和动作上下文。核心校验并计算身体变化、资源需求和能力结果，宿主将它们与世界副作用一起提交。

材料不足、世界账户不足、身体 revision 过期或安全策略拒绝时，不留下半次扣款。具体数据库事务、存储记录或提交协调由宿主实现，但要通过共同的原子性和重试契约验收。

核心保存寿命和身体状态，宿主提供保存后端及真实时钟，不各算一份年龄。Fabric 必须提供可直接使用的单机存储适配；Bong 可以对接既有数据库，而非把数据库类型暴露给公共 API。

## JNI 与发行

JNI 是待验证的技术建议。桥接只传有边界的数据、命令和结果，不跨边界暴露 Java 实体或 Rust 可写引用。错误可诊断，panic 不跨语言栈展开，世界卸载释放对应资源。

候选首批原生平台为 Windows x86_64 与 Linux x86_64，其他平台范围待发行矩阵明确。正式 JAR 包含其声称支持的平台所需原生库；用户不需要安装 Rust 编译器。未知平台或加载失败必须明确说明，不能回退成只有画面、没有结算的假成功。

客户端通过公共 Inventory UI 能力接入，服务端入口不加载 owo 或客户端专用类。依赖声明和打包方式需要实测；目前没有 Gradle 依赖坐标或安装命令。

## 最小接入验收

同一模板、配方、初始状态和宿主事实分别在两种环境完成：获得配方 → 调元 → 对应肌肉增益 → 攻击 → 真元回环境 → 保存 → 重开。最终身体结果一致，世界效果按各宿主的实际消费者结算。

基础模组不认识具体 Bong 功法 ID，Bong 也不维护第二套身体物理公式。缺少某个扩展算子时按能力协商失败，而不是私下替代。
