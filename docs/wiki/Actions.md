# 身体动作与模块占用

状态：已实现附属动作目录、多动作实例、受校验启停、占用查询、Protobuf 存档及指数恢复联动。Framework 不内置行走、跑步或吐纳 ID；生物与功法附属使用相同入口登记。

## 定义、实例与参数

| 消息或字段 | 含义 |
|---|---|
| `ActionDefinition` | 命名空间 `id`、正整数 `version`、显示名称、使用的 `tissue_ids` 和 `organ_ids`；同类局部引用不可重复 |
| `AddonBundle.actions = 6` | 附属登记的动作定义，通过 `meridian:actions_v1` 宿主能力校验 |
| `BodySnapshot.actions = 14` | 当前动作实例列表；可同时包含多个动作，也可包含同一定义的多个实例 |
| `ActiveAction` | 身体内唯一的 `instance_id`、固定完整定义、`started_millis`；开始时间使用身体时钟 |
| `ContentDefinitionKind.ACTION = 3` | 缺包查询使用精确动作 ID 与版本 |

组织、器官分别声明。例如呼吸动作可占用一块呼吸肌、注意组织和呼吸器官。声明器官不隐含占用其所在部位的全部肌肉；需要使用的组织必须显式列出。动作也可只作为活动标记而没有模块引用。

占用与负载分开：`start_action` 不扣耐力，实际做功仍通过 `exert_tissue`、`exert_tissues` 或 `IntakeQi.loads` 的力 N、功率 W、持续秒数结算。登记一个跑步动作不会自动产生跑步费用，也不会播放动画；宿主或功法执行器负责这些实际操作。后续效果扩展以同一身体事实为基础。

## 启停顺序

1. 宿主从 `AddonRegistry.actions()` 取得可信 `ActionCatalog`，装配到 `BodyCommandHandler` 的第八个参数。
2. 切换前先用 `advance_time` 按旧动作结清至事件时刻。
3. `start_action = 17` 只提交实例 ID、动作 ID 与版本。核心从目录解析，校验身体存活、模块存在及组织/器官和所属部位未失能。
4. `stop_action = 18` 按实例 ID 结束。停止一个动作不会删除其他同类动作或共同占用同一组织的动作。

启停要求 `ACTIVE` 且身体游标已结算到宿主当前时刻，否则拒绝。每次成功启停增加一次 revision，权限、私有策略、回执去重与原子提交沿用通用请求链。客户端不能上传任意组织名单，也不能通过直接停止宿主活动伪造休息；宿主策略负责动作来源和操作权限。

每具身体最多保存 32 个活动实例，作为输入规模上限；这不是境界、多重施法或控制力槽位。更具体的玩法限制由内容与宿主策略配置。常见拒绝码：`ACTION_NOT_FOUND`、`ACTION_ALREADY_ACTIVE`、`ACTION_NOT_ACTIVE`、`ACTION_LIMIT_EXCEEDED`、`MODULE_NOT_FOUND`、`MODULE_UNAVAILABLE`、`TIME_REQUIRES_SETTLEMENT`。

## 恢复、存档与中止

`BodyActions.usedTissues(body)` 返回各活动实例组织的并集。任何实例仍使用某块肌肉，它就不能自然恢复；其余符合条件的组织按[指数公式](Tissue-Recovery.md)恢复。时间结算没有逐秒循环。

动作实例保存完整占用定义，启动回执的 `action_definition = 8` 固定采用的修订。已启动动作不因内容包卸载或升级改变占用；卸载后仍可结算与停止，新启动返回缺失定义。一般动作在冻结时保留，死亡统一清空。开脉持有的动作须由开脉暂停/完成/中止解除；普通 `stop_action` 返回 `OPENING_BUSY`，避免任务和动作占用脱离。冻结会暂停开脉，保留合法库存和稳定体积。

器官可声明独立 `OrganEndurance`，实际疲劳为 `OrganState.fatigue_joules`。空闲器官按同一指数半衰期恢复；任何动作占用该器官时暂停恢复。开脉费用可分别绑定器官和组织，叠加在唯一状态中；声明占用本身不产生费用。

动作不会自行超时。宿主须在活动结束、断线、冻结前或恢复存档时明确继续还是停止。先按旧状态结清，再改变占用；撤销访问权前完成清理。权限撤销后的清理由可信宿主提交，公共框架不会绕过授权。

通用吐纳编排可绑定 `BreathingProfile.body_action`。有自然恢复能力的呼吸/注意组织必须绑定一个同时包含它们和呼吸器官的动作。有效吸呼时启动，停气、满吸、排空、结束或关闭时解除本会话实例；其他动作占用保留。停止允许重新读取最新身体版本进行清理，但继续摄入仍遵守原计划版本检查。若清理提交失败，宿主须处理错误并重试，不能直接遗弃会话。
