# 基础数据定义

状态：已实现 Java 17 不可变数据值与构造校验，源码位于 `server/src/main/java/dev/kizuna/meridian/core/`；对外数据交换采用 [Protobuf v1](Protocol-and-Security.md)，源码在 `shared/src/main/proto/`，生成类与核心值之间由服务端的 `BodyProtobuf` 映射。工程分为 `client`、`server` 两个 Gradle 子项目；`meridian-core` 是服务端数据层的职责名称，没有独立子项目或已发布依赖坐标。

这一层没有 Minecraft、Fabric、Bong 或具体功法依赖。数据值本身不推进时间、不执行配方、不写存档，也不授权外部调用者覆盖权威身体。Java 模型是参考实现，其他语言按同一 Protobuf 与行为契约接入；纯算子及[变更入口](Protocol-and-Security.md)已支持寿元支出、时间推进、真元运输、器官加工、组织做功及寿尽释放。

## 模板、实际构型与实例

| 类型 | 已实现职责 |
|---|---|
| `DefinitionId` | 内容的 `namespace:path` 标识，用于模板、组织类型、器官类型和真元属性 |
| `BodyId` | 宿主分配的稳定身体实例标识，不存宿主实体对象 |
| `BodyTemplate.Reference` | 模板标识及正整数内容版本 |
| `BodyTemplate` | 出生构型定义，不包含某个角色的余额、年龄或伤势 |
| `BodyStructure` | 部位、组织、器官、经脉、端口和连接，以及这套构型的有效结构参数 |
| `BodySnapshot` | 模板来源引用、当前实际构型、逐模块状态、境界、真元、寿命、时间游标与 revision |

模板与实例可以安全共用同一个不可变结构值。角色改造后创建新的实际 `BodyStructure`，原模板和其他身体保持原值。加载角色时使用保存的实际构型，不重新套用出生模板；模板引用只是来源，不要求实际构型始终等于模板。

具体出生构型由生物附属模组提供，人体也是独立附属内容；主框架只定义数据类型与通用校验。人体包负责初始定义，创建后的实际构型和运行状态仍由权威核心保存。通用器官摄入能力及[模板/类型/配方的包级注册](Addon-Integration.md)已实现，死亡条件契约仍待补齐，职责边界见[架构与职责](Architecture.md)。

没有自动“创建满血满元角色”的工厂方法。初始化方必须显式提供所有状态；缺一条状态就拒绝创建快照，不默认补全。所有列表进行防御性复制，返回值不可修改。

局部部位、组织、器官、经脉、连接 ID 分别在所属身体的同类模块内唯一；端口 ID 在整具身体内唯一。多个身体可以使用相同局部 ID，对外定位需要同时提供 `BodyId`。内容 ID 的语法校验不等于注册成功；`AddonRegistry` 已检查命名空间归属、依赖和类型引用，输出不可变模板及配方目录。已有身体仍可独立于出生模板恢复，迁移策略尚未实现。

## 身体模块

| 定义与状态 | 基础字段 |
|---|---|
| `Anatomy.PartDefinition` / `AnatomyState.Part` | 部位名称、最大 HP / 当前 HP |
| `Anatomy.TissueDefinition` / `AnatomyState.Tissue` | 类型、归属部位、最大 HP、疲劳容量、端口、基础力量 N/爆发功率 W/耐力 J / 当前 HP 与疲劳 |
| `Anatomy.OrganDefinition` / `AnatomyState.Organ` | 类型、归属部位、最大 HP、端口、真元容量、端口共享吞吐、可缺省摄入能力 / 当前 HP、缓存、可缺省加工任务 |
| `Anatomy.OrganIntakeCapability` | 正数 `maxQiPerSecond`，元/模拟秒；独立于端口吞吐，保存在实际构型中 |
| `OrganRecipe` / `OrganProcess` | 配方 ID/版本、器官类型、输入输出、时长、最低境界 / 已固定配方、完成时刻、是否到期阻塞 |
| `Anatomy.MeridianDefinition` / `MeridianState` | 覆盖部位、内腔与外壁容量、各自液态参照、吞吐、承受度、疲劳容量、端口 / 两类账户、疲劳、完好或破裂或断裂状态，以及必填的逐脉开拓数据 |
| `MeridianOpening` | 首次建立意念响应的 `stage` 与无量纲 `progress`，由所属经脉实例持有 |
| `Anatomy.Port` | 端口 ID，输入、输出或双向方向 |
| `Anatomy.Connection` | 连接 ID、起止端口、相对阻力、距离 |

肌肉、皮肤、骨骼等由组织类型 ID 区分，特异器官也使用内容 ID，不在通用层加入固定种族分支。一条经脉可经过多个已存在的部位；肌肉和器官可以有自己的输入输出端口。器官的转换效率和产物属于配方，未错误地固定到端口上。

`OrganDefinition.intake` 缺省表示不具备环境摄入能力，明确声明后由 `OrganIntake.apply` 按可信活动区间摄入原始真元。它检查生命、器官/部位 HP、速率、缓存和加工占容以及在途预约，并消费身体时间；来源库存与共享供给预算由同一事务核验。原始属性保留，动态炼化效率仍待实现，详见[环境摄入与交换](Environment-Qi.md)。

连接为有向边；双向通路声明两条边。允许合法循环和暂不连通的模块，拒绝不存在的端口、方向冲突、重复边与同端口自连。不要求固定左右结构，也不要求每个部位拥有经脉；全身暂时没有经脉的数据仍可表达基础生命。数据图的合法循环不代表未来执行器可以执行零时间无限循环。

总体生命比例只使用 `sum(部位当前 HP) / sum(部位最大 HP)`，由 `partHpRatio()` 派生。组织和器官 HP 表示局部状态，不再次加入这个总和。伤害如何同步影响部位与内部组织、头部等关键部位如何触发死亡，仍属于待实现的伤害规则；当前构造器不会自动宣判死亡。

## 经脉开拓数据

`MeridianState.opening` 必须显式提供 `MeridianOpening(stage, progress)`。开拓属于某条经脉的实例事实，不写入共用的出生构型，也不从损伤、余额或境界推断。

| 阶段 | 进度 | 含义 |
|---|---|---|
| `UNOPENED` | 必须为 `0` | 尚未开始建立意念响应 |
| `IN_PROGRESS` | `0 <= progress < 1` | 已开始但尚未完成，可保存暂停后的进度；零表示刚开始 |
| `OPENED` | 必须为 `1` | 已完成首次开拓 |

进度必须是有限数，使用严格的 `0–1` 边界，不采用真元账本的 ULP 上限容差。阶段与进度不符时拒绝整个数据值。`IN_PROGRESS` 表示持久化阶段，不表示后台正在执行任务；进度也不是额外的灵气余额、经过秒数或后续容量成长比例。

未开拓经脉可以存有真元，已开拓经脉也可以受损或断裂。所有储量仍计入唯一总账。运输、时间结算和死亡清账保留开拓事实，Protobuf 往返保留每条经脉自己的阶段与进度。

当前只实现数据与校验；运输尚未检查开拓门槛，聚灵、开拓任务、进度推进、引元口和成长操作仍待实现。数据构造和解码不启动任务，也不扣资源或开放客户端修改入口。

## 真元明细与总账

`Qi` 表示一条相态、属性、数量。相态定义游离、气、液、固、通灵、化虚六种；化虚使用 `QiPhase.VOID` 标识，具体性质和转化规则尚待设计。`QiAttribute` 是可扩展内容 ID，内置无属性与五行标识；两个附属包的自定义属性不会被压成一个 `CUSTOM` 值。

`QiInventory` 保存一个账户内的多种真元：不同相态、不同属性可共存；同相态同属性只允许一条正数明细，空账户用空列表。同类 `Qi` 可以加减，不同类型不能借加法完成相变或属性转换，扣减不能透支。

| 位置 | 持有者 | 汇总方式 |
|---|---|---|
| 内腔 | `MeridianState.lumenQi` | `BodySnapshot.lumenQiTotal()` |
| 外壁 | `MeridianState.wallQi` | `BodySnapshot.wallQiTotal()` |
| 在途 | `QiTransit.cargo` | `BodySnapshot.transitQiTotal()` |
| 器官 | `AnatomyState.Organ.buffer` 与 `process.recipe.input` | `BodySnapshot.organQiTotal()`，缓存和加工原料各计一次 |
| 全身 | 不设独立可写余额 | `BodySnapshot.totalQi()`，以上四项相加；预计产物不计入 |

外壁储备不等于立即可用真元；内腔汇总也不表示任意目标都可立刻取用。`QiTransit` 记录唯一 ID、连接、货物、到达时间、预约吞吐及 `MOVING`/`BLOCKED_ROUTE`/`BLOCKED_CAPACITY` 状态。在途已经从源账户扣除，尚未进入目标；目标预约额度从这些记录派生，不是另一份资源余额。移动中记录须晚于结算游标，阻塞记录须已到达。

`QiTransport.start` 与时间算子已执行经脉/器官间扣源和到达入账；加工从缓存扣除输入，再按完成事件兑现输出与环境损耗。事务一起保存身体、回执和环境释放。数据构造器只校验单个快照，不能证明前后守恒或先前是否扣过源。吞吐共享、容量预留与阻塞规则见[经脉运输](Meridian-and-Qi.md)，组织单位和配方规则见[功法扩展](Technique-Addons.md)。

环境供给与身体账户分离：新增 `EnvironmentQiOffer`、`EnvironmentQiExchange` 和 `EnvironmentQiReceipt`，全部直接由 Protobuf 定义。供给含来源版本、适用身体、可用明细、总速率及同域有效时间；交换记录吸收与释放毛额；回执绑定身体和来源的新版本。字段、单位与宿主事务要求见[环境真元交换](Environment-Qi.md)。编解码不会生成或转移真元，环境来源的实际存档由宿主管理。

容量和当前余额分别存储，增大容量不会自动填充真元。`BodyStructure.capacityRatio()` 使用 `(内腔有效容量 + 外壁有效容量) / (内腔液态参照 + 外壁液态参照)`，无经脉时为零。外壁有效容量大于零时必须提供外壁液态参照；不能凭空增加无参照的储备空间。

器官缓存是局部加工与转运空间，不是人体独立真元池；器官容量不进入经脉境界容量比，不能靠增加缓存升级。加工输入计入器官容量但不能发运；一个器官只持有一笔加工事实。运行中的完成时刻须在游标之后，阻塞的完成时刻不得在游标之后，配方器官类型必须匹配。

`Realm` 保存六境目标比例 `0.01 / 0.1 / 1 / 10 / 100 / 1000` 和基础主动任务位 `1–6`；第六境化虚使用 `Realm.VOID_TRANSFORMATION`，延续每境容量比十倍、任务位加一的设定。当前境界作为已确认状态保存，不由一次填充量或容量比直接推断。突破、压强、混相占容与密度变化没有实现；现阶段容量字段是规则给出的有效元数上限，并非物理体积。相变和临时超载规则实现时，还需明确如何生成这个上限及结算破裂，不能悄悄丢弃溢出真元。

## 单位、寿命与时间

| 字段 | 当前单位与约束 |
|---|---|
| 真元数量、内腔/外壁有效容量、液态参照 | 元；非负有限 `double`，内腔容量和参照为正 |
| 吞吐及在途预约吞吐 | 元/模拟秒，正有限数；两端收发共享额度，批次有效流量为预约吞吐除以 `(1 + 阻力)` |
| 连接距离 | 米，正有限数；宿主负责模型尺度换算 |
| 连接阻力、经脉承受度 | 相对系数；阻力用于批次运输，承受度的超载/损伤公式待实现 |
| HP、疲劳 | 各模块自身计量，上限由当前结构声明，不是百分数 |
| 年龄、寿命上限、额外寿元支出 | 生物秒；非负有限 `double` |
| `TimeCursor.elapsedMillis`、`QiTransit.arrivalMillis` | 宿主模拟毫秒，非负 `long`，不等同系统时间戳 |
| `BodySnapshot.revision` | 非负 `long`，整个权威身体状态的版本 |
| `schemaVersion`、模板内容版本 | 分开记录；当前只接受身体 schema 2，线协议仍为 1 |

寿命使用 `VitalityState(ageSeconds, lifespanLimitSeconds, spentLifespanSeconds, dead)`：剩余寿命为 `max(0, 上限 − 年龄 − 额外支出)`。`dead` 记录已完成的生命状态判定；构造数据本身不触发死亡，寿尽与释放由 `BodyTimeAdvancement` 和事务入口执行，复活尚未实现。

`TimeCursor` 另外记录时钟域与世代；只有域和世代相同的时间位置才可比较。快照已结算到该位置，移动中在途须在未来，已到达受阻货物显式保留阻塞状态。模拟/生物时间折算、冻结模式和防止重复推进已由[时间算子与宿主时间源](Body-and-Persistence.md)实现；具体离线调度与跨世代迁移仍由后续宿主接入完成。查询、客户端插值和寿元支出不会隐式推进年龄或移动真元。

## 校验与验证范围

构造器自动检查空值、标识格式、有限数、上下限、模块 ID 唯一性、结构引用、状态与模块逐 ID 对应、端口方向及在途时序。包括所有明细为有限数但相加溢出的情况，不只比较列表数量。

目前数量使用 `double`。正数上限比较只容忍上限值四个 ULP（机器精度步长）以内的舍入误差，避免 `0.1 + 0.2` 被当作超过 `0.3`；零上限不允许正数，舍入导致的极小扣减负尾差归零。这不是游戏中可配置的透支额度。Protobuf 保留二进制 `double` 与 `int64`，不经过 JSON 数字；其他语言运行账本仍须遵守相同精度策略与守恒测试。

运行 `./gradlew test` 使用 Java 17 工具链。契约测试包括非人构型、没有经脉时的基础生命、模板与实例隔离、不可变列表、真元混相/自定义属性、分位置总账、非法结构与状态、在途记录、容量增长不生成真元、寿命展示和六境常量。

模板与快照二进制编解码、查询请求/响应契约已实现；`BodyProtobuf` 解码后重新调用上述构造器，不绕过校验。`./gradlew build` 还验证固定协议字节、非法载荷、六境与混合账户往返及分发产物。

Java 参考查询处理器已通过宿主注入的读取策略和快照来源提供只读请求处理，见[宿主接入](Host-Integration.md)。这不会使数据对象变成可由客户端覆盖的权威状态。

已实现 `LifespanSpending.apply` 非致死支出：正数剂量严格小于剩余寿命，死体、版本耗尽与浮点不可见支出拒绝，成功只增加已耗寿元及 revision。授权、去重、事务及私有策略由服务入口提供，不属于数据构造器。

已实现 `BodyTimeAdvancement.apply`：同域同世代时间推进、固定老化倍率、寿尽边界、经脉/器官到达、加工完成与阻塞结算、冻结运输和加工以及死亡全账户清账；结果携带加工损耗与死亡释放，宿主事务负责环境入账。`nextEventBoundary` 合并寿尽、运输到达与加工完成。`QiAccounting` 共用按种类扣账及防止整笔入账被浮点吞掉的规则。

尚未实现：开拓任务与调用门槛、磁盘持久化、连接认证与网络、实际宿主调度和实体死亡、组织真元缓存与增益、连续流/自动多跳、环境退化、修炼/突破、知识/控制任务、成长来源审计及其他世界资源事务。后续在各自切片中补充契约。
