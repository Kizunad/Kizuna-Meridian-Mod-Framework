# 环境区域、浓度与传播配置

状态：TOML 读取、完整配置 Protobuf、有界校验、空间定义、分片边界缓存及[按地形生成初始灵气与边界倍率](Terrain-Qi-Generation.md)已实现。取消世界扫描、方块变化接入和修炼室自动识别；区域库存、实际世界生成接入、扩散调度、多人供给分配和交换原子事务仍待实现。本页的速率是宿主计算候选量的规则，实际扣账遵守[环境交换契约](Environment-Qi.md)。

## 生成方向

沿用可配置的 chunk 区域作为空间基础。生成器为区域建立初始真元库存，为相邻区域的共享边界分配传播倍率；运行时根据实际库存计算浓度，再由浓度差驱动扩散。随机的是初始条件和传播能力，不是每次结算的方向或转移数量。

生成器按以下规则生成初始候选；地形区间、五行偏好及接入约束详见[地形生成](Terrain-Qi-Generation.md)：

- 用世界种子、维度、区域坐标和生成规则版本确定初始区域数据。已存在区域恢复当前库存，不能在卸载、重载或重启时重新发放初始灵气。
- 一对相邻区域只生成一条共享边界；以排序后的两个来源 ID 确定稳定边界身份，避免先加载哪一端影响结果。随机倍率只生成一次，并随边界快照保存。
- 倍率为有限非负数，0 表示阻断，允许特殊边界大于 1；默认在 `[0.25, 1.00)` 内均匀抽取。实际流量仍乘浓度差与接触面积，库存耗尽或浓度平衡时停止转移。
- 普通区域的邻接和接触面积直接由区域尺寸及有效高度计算。房间、通道可以由生成器或内容定义显式登记，不从世界方块推断。
- 方块放置、破坏、门开关与爆炸不改变此环境图。参数或区域定义的显式变更走已有版本和失效机制。

`TerrainQiGenerator` 把随机倍率写入 `EnvironmentBoundaryPatch.transmission`，普通边界用一个分片复用现有缓存。方块传播系数保留为可选的材质预设查询，不要求读取世界方块，也不额外重复乘到随机倍率上。生成输入和区域初始候选已有 Protobuf 定义，实际生成记录、位置映射与当前库存由宿主一起保存。

## 配置入口

默认文件位于 `server/src/main/resources/meridian-environment.toml`，构建后进入服务端 JAR 根目录。使用 tomlj 1.1.1 解析标准 TOML；客户端只接收 protoc 消息，不依赖 TOML 解析器或环境计算。

| Java 入口 | 行为 |
|---|---|
| `EnvironmentConfigLoader.defaults()` | 读取 JAR 内的完整默认配置 |
| `EnvironmentConfigLoader.load(Path)` | 读取宿主指定的 UTF-8 文件，将覆盖项合并到默认配置 |
| `EnvironmentConfigLoader.parse(String)` | 解析 TOML 文本覆盖项，适合宿主已有配置读取流程的情况 |
| `EnvironmentConfigProtobuf.encode/decode/validate` | 交换、恢复和验证完整的 `EnvironmentQiConfig` |
| `new EnvironmentQiRules(config)` | 校验配置并建立只读方块系数索引，提供下述纯计算 |

文件路径由宿主选择，例如 `config/meridian-environment.toml`；当前库不注册 Fabric 自动加载入口、不自动创建文件。空文件与省略项沿用默认值；显式给出的文件无法读取、TOML 语法错误、未知键、错误类型或非法数值均报错。文件上限为 256 KiB，重复键由 TOML 解析器拒绝。加载在启动或宿主明确切换规则时执行，不在每个 tick 读文件。

最小覆盖示例：

```toml
[region]
size_chunks = 2

[absorption]
volume_blocks_per_second = 1.0

[diffusion]
speed_blocks_per_second = 1.0
default_block_transmission = 0.10

[diffusion.blocks]
"addon:qi_conduit" = 2.5
"addon:sealed_wall" = 0.0
```

方块 ID 必须写成带引号的 `namespace:path`；按精确 ID 覆盖，其余内置方块值继续保留。加载器不读取 Minecraft 注册表、不按名字后缀推断材质。显式指定材质预设的边界可以查询这些系数；世界中的同名方块及其开关状态不会自动影响区域传播。

## 完整配置契约

消息定义位于 `shared/src/main/proto/kizuna/meridian/v1/environment.proto`。TOML 是本地配置入口，跨进程和跨语言仍交换 Protobuf，不传递一套平行 JSON。宿主接收的是补齐后的完整值，不依赖接收端重新加载默认文件。

| TOML 字段 | Protobuf 字段 / 编号 | 默认及范围 |
|---|---|---|
| `config_version` | `config_version = 1` | 2；独立于身体 schema 和来源 revision |
| `region.size_chunks` | `region_size_chunks = 2` | 1；正 int32，横向正方形区域边长 |
| `absorption.volume_blocks_per_second` | `absorption_volume_blocks_per_second = 3` | 1.0；有限非负，格/模拟秒；0 暂停吸收 |
| `diffusion.speed_blocks_per_second` | `diffusion_speed_blocks_per_second = 4` | 1.0；有限非负，方块边长/模拟秒；0 暂停扩散 |
| `diffusion.default_block_transmission` | `default_block_transmission = 5` | 0.10；范围 `[0, 1)` |
| `diffusion.blocks` | `block_transmissions = 6` | 完整有效表；`BlockQiTransmission` 保存 `block_id = 1` 与 `transmission = 2` |
| `generation` | `generation = 7` | 算法版本 1、主世界地形表、未知群系范围和随机边界倍率；详见[生成配置](Terrain-Qi-Generation.md) |

数值 `optional` 在消息中业务必填，合法的 0 也要显式保存。方块 ID 唯一，系数允许任意有限非负值，包括大于 1；三种空气 ID 必须显式存在且恰好为 1。消息规模、未知字段和文本限制沿用[协议边界](Protocol-and-Security.md)。该消息是可信宿主配置，不能注册成客户端修改世界规则的命令。

## chunk 区域与供给

`size_chunks = N` 表示横向 `N × N` 个 chunk，每个 chunk 的横向尺寸为 `16 × 16` 方块。高度采用宿主世界有效高度，不把 chunk 当成立方格。`regionCoordinate(chunkCoordinate)` 向下取整，X、Z 分别调用；区域身份还必须包含宿主维度标识。

```text
区域 X = floor(chunkX / N)
区域 Z = floor(chunkZ / N)
区域体积 = (16 × N)² × 有效高度
```

例如 N=2、高度 384 时体积是 393216 格；chunk -1 与 -2 同属区域 -1，chunk 0 与 1 同属区域 0。`regionVolumeBlocks(heightBlocks)` 计算完整区域体积；宿主若采用有效子体积，应在浓度计算时明确提供实际体积，并保证两个区域使用相同口径。体积来自区域定义，不随挖掘方块变化。

这里“格”指一个方块体积；“元”沿用真元总量单位，相态和属性不改变加账单位。

```text
浓度 C（元/格） = 区域真实库存 Q（元） / 区域有效体积 V（格）
环境侧吸收上限（元/秒） = C × 有效采集体积速度（格/秒）
```

`concentration(inventory, volumeBlocks)` 与 `absorptionLimitPerSecond(inventory, volumeBlocks)` 从库存直接派生，没有单独可写的浓度字段。默认采集速度为 1 格/秒：浓度 0.2 元/格时上限是 0.2 元/秒，浓度 2 时上限是 2 元/秒。不会给每个区域或生物固定发放 2 元/秒。

宿主还需要按器官能力、身体接收空间、剩余库存及多人共享预算限制本身体额度。`EnvironmentAbsorption` 已提供短固定窗口的离散参考：开启窗口时按此公式计算速率，窗口内持续扣真实库存并登记共享速率占用；窗口结束后按剩余浓度重新计算，不能通过换来源 revision 清空预算。窗口长度由宿主安排，不能把起点浓度无限积分，也不能给每个生物重复使用全部共享预算。库存和体积都必须有效，零库存的供给为 0。具体时间与事务约束见[环境摄入](Environment-Qi.md)。

## 边界传播速率

`contactTransmission(firstBlockId, secondBlockId)` 合成相邻两格的系数。两格各贡献半段阻力，使用调和平均；任意一格为 0 都阻断：

```text
k接触 = 2 / (1/k左 + 1/k右)
```

空气与空气为 1；石头与石头为 0.1；空气与石头约 0.1818；两个 2.5 特殊方块仍为 2.5。这是保留的材质系数合成工具；显式使用材质模板时，按定义的分片面积加权即可。默认随机区域直接使用已生成的边界倍率，较低阻力不会凭空增加资源。

`candidateDiffusionPerSecond(sourceC, targetC, area, transmission)` 使用正浓度差：

```text
候选流量（元/秒） = max(0, C源 - C目标)
                  × 基准速度（方块边长/秒）
                  × 接触面积（方块面数） × k接触
```

浓度差 1 元/格、接触面积 10 个方块面、基准速度 1 时，空气边界候选为 10 元/秒，石头为 1 元/秒，2.5 增强边界为 25 元/秒。方向反转、相同浓度、零面积或阻断时返回 0。无限值、负值与运算溢出会被拒绝。

这些是候选速率，尚未操作账本。正式推进要按相态/属性保持守恒，并统一限制多个邻居的源区总支出。一对隔离区域的净转移不能越过平衡量 `(C源 - C目标) / (1/V源 + 1/V目标)`；多邻区同时结算还需共同分配并重新判断平衡，不能把每对独立结果直接扣账。状态变化和低频事件决定推进时刻，静止区域可停止调度。

## 安装与验证

### 区域、房间与通道定义

普通区域采用 chunk 区域的均匀浓度。房间和通道类型保留，供生成器或内容包显式提供范围、体积与连接；它们是环境空间定义，不要求对应一个被自动识别的世界建筑。

`EnvironmentSpace` 定义独立混合空间：`protocol_version = 1`、`source_id = 2`、`kind = 3`、`volume_blocks = 4`。类型包括 `REGION_BACKGROUND`、`LOCAL_ROOM` 和 `LOCAL_CHANNEL`。空间复用环境交换的来源 ID；体积必须为正，浓度由该来源的唯一库存派生。它是空间描述，不是另一份库存，也不是让客户端自行圈定房间的请求。

| 场景 | 处理方式 |
|---|---|
| 普通区域 | 按配置的 chunk 区域混合，生成初始库存和共享边界倍率 |
| 房间定义 | 显式登记独立来源与边界参数，所有对外倍率为 0 时表示封闭空间 |
| 通道定义 | 按定义的段落登记来源，通过边界连接，长通道可以拆成多段 |
| 房间跨 chunk | 空间身份不按 chunk 截断，定义记录它在各背景区域占用的体积 |
| 定义变更 | 更新相关边界；空间归属改变时先停用相关边界，再迁移账户 |

“房间”类型本身不保证密闭，传播由定义中的全部对外边界决定。例如显式选用石墙预设的边界系数为 0.1，仍会缓慢渗透；只有全部对外通路均阻断时，传播才为 0。系数大于 1 只增强传播，不自动创建空间或产生灵气。实际建筑墙体改变不触发此定义更新。

独立空间的几何范围不可重叠，位置查询只能选中一个环境来源。房间划出时，宿主先结算旧拓扑区间，再按每种相态、属性从背景账本转移对应份额，并扣除对应体积。例如从均匀的 1000 格背景中划出 100 格房间，各类真元按 10% 转入房间，剩余 900 格保留 90%；两个空间初始浓度相同。跨区房间分别从各背景贡献部分取账，不复制整个区块的库存。

显式解除房间定义时，其当前库存和体积归并到实际接收空间；已经聚集的真元不能按原始比例重置。拆分、合并和改道由宿主原子发布空间映射、账户、来源版本及连接，任意失败都保留旧状态。背景体积完全被划走时移除其活动空间，不能用零体积计算浓度。这些定义变更和账本操作尚未实现，消息校验不能证明空间没有重叠。

### 分片边界缓存

`EnvironmentBoundaryCache` 缓存两个来源之间的传播能力。同一边界只登记一份，两端共同使用。普通生成边界用一个分片保存定义的接触面积和随机倍率；需要多个端口的内容定义可显式提供多个分片。

```text
分片贡献 = 分片面积 × 定义的传播倍率
边界传播能力 = 所有分片贡献之和
候选流量 = 正浓度差 × 基准速度 × 缓存的边界传播能力
```

首次建立区域时，用生成结果构建完整边界快照；已有区域从存档恢复。只有边界定义或传播参数显式改变时才更新分片，常规库存变化仅改变浓度，不重建传播能力缓存。

运行时查询直接使用总贡献，不访问方块、不遍历分片。每次增量更新读取缓存中的旧贡献，再加上新的绝对贡献；不会信任消息提供的旧值。Java 参考实现用精确十进制累计保留小贡献，只在变化时运算；常规速率查询使用缓存的 double。这样临时插入巨大增强端口再拆除时，不会因浮点相消丢掉原来很小的通路。

| 契约/入口 | 内容与约束 |
|---|---|
| `EnvironmentBoundarySnapshot` | 协议版本、边界 ID、两个不同来源 ID、缓存 revision、规则世代、ready、分片列表 |
| `EnvironmentBoundaryPatch` | 边界内唯一 ID、正面积、有限非负接触系数；0 为阻断，大于 1 保留 |
| `EnvironmentBoundaryPatchUpdate` | 边界 ID、预期缓存版本、规则世代，以及替换分片或删除分片的 oneof |
| `EnvironmentTopologyProtobuf` | 空间、边界和增量更新的有界 encode/decode/validate |
| `new EnvironmentBoundaryCache(snapshot)` | 从可信生成定义或已核实的存档重建索引与总贡献 |
| `apply(update)` | 只更新一个分片，成功后 revision 加 1；重复版本、错误边界和数值越界都拒绝且不修改缓存 |
| `invalidate(expectedRevision)` | 版本加 1 并标记未就绪；保留旧分片供重建诊断 |
| `candidateDiffusionPerSecond(rules, rulesRevision, sourceId, sourceC, targetC)` | 读取单方向候选速率；sourceId 须为端点，targetC 对应另一端；未就绪或规则不匹配时拒绝 |
| `snapshot()` | 在保存或跨语言交换时复制分片，正常查询无需调用 |

完整边界上限沿用协议限制：4096 个分片、1 MiB 消息。更大边界按更大面积聚合分片，位置归属由宿主保存。缓存更新时也检查完整快照大小，防止连续小更新产生无法保存的数据。缓存不持有真元，流量只代表候选；多边界共享库存、平衡限制和原子扣账仍遵守前文规则。

`rules_revision` 是宿主安装参数时分配的非负规则世代，必须与实际传入的 `EnvironmentQiRules` 对应；与配置格式版本及来源账户版本分开。宿主在单一事件线程内使用缓存，或自行串行化访问；该类不自行注册线程、定时器或网络处理器。

生成定义未就绪、空间归属改变或规则失效时，暂停受影响的传播；来源归属不确定时，也暂停相关吸收与释放提交。未就绪不能被当成密闭的零流量结果。宿主核对定义版本与规则世代，保持缓存 revision 单调前进，再原子替换为完整 `ready=true` 缓存；过期候选丢弃重算。恢复缓存也须核对这两类依据，不能只相信存档里的 ready。

持续扩散由宿主低频调度；浓度平衡且无外部变化时休眠，库存、端口或拓扑定义变化后唤醒相邻连接。长期运行成本主要取决于活跃边界数，而非世界方块总数。当前已实现生成候选、缓存和候选流量计算，实际生成接入、休眠调度与世界账本执行仍待接入。

### 配置安装与回归

宿主加载配置后持有一个 `EnvironmentQiRules`，供 `EnvironmentAbsorption.initialize/renewWindow` 计算供给速率。配置不写入身体快照；区域库存与预算通过 `EnvironmentQiSource` 一起保存。切换配置时须先结算旧规则窗口，再按新配置续窗并更新来源版本；改变区域尺寸还需要重分账本，不能只重新算区域坐标。当前没有自动热重载。

`EnvironmentConfigurationTest` 保留配置文件到 Protobuf 往返、非法配置拒绝、负 chunk 坐标、浓度驱动既有交换额度、屏障阻断和大于 1 系数的整体回归。完整构建还校验客户端/服务端 JAR 与协议包使用同一份 schema 和描述集。

`EnvironmentTopologyTest` 保护房间/通道的协议往返、边界分片替换与恢复、重复事件拒绝、规则失效暂停和极大/极小贡献并存时的正确更新。`TerrainQiGenerationTest` 保护地形配置/协议、确定性向量、未知群系、五行分配及共享边界；实际世界转账仍需执行层验收。
