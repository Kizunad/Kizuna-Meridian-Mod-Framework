# 组织耐力与精力恢复

状态：已实现通用休息恢复、Protobuf 定义、可信时间结算和内存事务回执。肌肉与注意组织使用同一套规则，具体组织 ID、速率与人体数值由生物附属提供；真实宿主负责判定休息区间。

## 数据与所有权

| 字段 | 所有者与含义 |
|---|---|
| `TissueDefinition.rest_recovery_per_second = 9` | 实际构型中的恢复能力，每模拟秒减少多少疲劳单位；有限非负数，缺省或零表示不自然恢复 |
| `TissueState.fatigue` | 权威身体保存的唯一疲劳值；耐力、精力继续由该值和组织能力派生 |
| `TimeAdvancePlan.resting_tissue_ids = 4` | 宿主确认整个未结算区间处于休息状态的实际组织 ID 列表；不得重复，空表表示没有组织恢复 |

内容包提供速率，主框架不按组织名称猜测数值。模板含有正恢复速率时，附属加载器要求宿主声明 `meridian:tissue_recovery_v1`；该能力意味着实现本页的行为合同，而不只是能够解析新增字段。

## 计算规则

身体处于 `ACTIVE` 模式，组织被列入休息名单，且组织及所属部位 HP 均大于零时：

```text
恢复秒数 = (实际结算毫秒 − 原结算毫秒) / 1000
恢复后疲劳 = max(0, 原疲劳 − 休息恢复速率 × 恢复秒数)
疲劳余量比例 = max(0, 1 − 恢复后疲劳 / 疲劳容量)
可用耐力 = 基础耐力 J × 完好比例 × 疲劳余量比例
```

完好比例沿用组织与部位的较低 HP 比例。恢复只减少疲劳，伤势仍然限制可用力量、功率与耐力。例如疲劳容量 100、当前疲劳 70、恢复速率 2，休息 10 模拟秒后疲劳为 50；若完好比例为 0.5，则可用耐力为基础值的 25%。

恢复按模拟秒计算，独立于寿命的生物时间倍率。长区间先判断是否已足够恢复全部疲劳，再计算剩余量，避免速率与时长相乘溢出。正恢复量小到浮点无法改变疲劳时，整次结算返回 `NUMERIC_LIMIT`，宿主可合并区间后重试；不能只移动游标而漏掉恢复。

`LIFESPAN_ONLY` 保留原疲劳并推进游标，解冻后仅恢复新活动区间。跨越寿尽时只计算死亡边界之前的时间；死体再次推进返回 `BODY_DEAD`。零时长不恢复。失能部位或组织保持原疲劳，恢复不增加 HP、真元或基础耐力上限。

## 宿主接入与事件边界

客户端仍只提交 `advance_time {}`。宿主在 `BodyTimeSource.resolve` 返回目标时间、模式、老化倍率及休息名单；名单描述从身体旧游标到目标的整段事实，不能根据请求到达时“正在休息”倒推整个过去区间。

1. 开始休息前，先按旧名单结算至切换时刻，再登记新的休息名单。
2. 开始做功前，先结清此前休息区间，再移除实际参与的组织，执行做功与后续活动。
3. 做功期间处理其他组织的休息；动作结束、暂停、断线或离线策略变化时，再按旧条件结清并切换。

宿主可按组织区分，例如一处肌肉在工作时，其他未参与的组织可以休息。框架不通过“最近没有收到客户端请求”推断休息。身体归属、版本校验和私有策略照常执行。

普通做功仍是按已结算时刻消费预算的单次命令，`duration_seconds` 用于计算工作量，不自动创建活动计时器。持续动作的真实活动区间由宿主记录。`IntakeQi.loads` 已明确声明本段摄入使用的组织，因此核心从本次有效休息名单排除这些组织，按起点能力验算负载，保留其他组织的恢复。摄入回执保存实际采用的名单。

恢复不创建每 tick 或每秒后台任务，也不增加 `nextEventBoundary` 的周期唤醒。宿主在现有事件、状态切换或需要新能力值时结算一次，随后读取新快照；满恢复本身没有必须唤醒的副作用。一次计算建立模块索引并遍历组织，复杂度随身体模块数线性增长，与经过一秒还是一天无关。客户端可以插值展示，查询本身不写账。

## 提交、存档与验证

恢复与同段年龄、运输及加工结果一并生成候选身体，整个提交只递增一次 revision。摄入期间的恢复、组织代价、环境扣账和身体入账也在同一事务完成，任何失败均不发布部分结果。

保存实际构型中的速率、组织疲劳、身体时间游标和成功回执。回执保留可信时间计划；加载后从已保存游标继续，重试返回原结果，不重新读取时钟或再次恢复。宿主同时保存用于切分后续时间的活动与休息事实。

整体回归覆盖非人肌肉与注意组织、不同恢复速率、冻结与寿尽、失能、满恢复、数值边界、协议和快照往返、权限拒绝、重试去重，以及摄入代价与其他组织恢复的原子性。人体恢复初值和实际玩家休息状态接入仍由 Human 与宿主配置。
