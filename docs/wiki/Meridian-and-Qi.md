# 经脉、真元与成长

状态：以下产品方向已确认，标为建议的方案和数字仍待细化与实机平衡。[Java 17 核心](Data-Definitions.md)已提供构型、混相/多属性账本、经脉与器官之间的批次运输、器官单批次加工及组织能力/做功。逐脉开拓、引元口、工厂自动运行、相变突破和成长仍待实现。

## 身体与经脉

经脉拥有天然倾向，同时允许后天改变。维持基础生命功能的前提下可改造身体；限制来自材料、操作、承载、恢复和控制难度，不由出生模板永久锁死路线。没有经脉的局部部位仍可存活，基础生命不依赖真元。

人体布局以中医经脉观念为灵感；左右实例、交汇和实际部位映射由模板声明。其他生物可有不同的部位与通路，不强制二十脉或人形肢体。

每条经脉包含：

- **内腔**：存留真元，具有局部容量、吞吐和承受度；该脉完成开拓后才能被意念主动取用。
- **外壁**：类似脂肪的长期储备，不能直接施招，须先动员进内腔。外壁容量约为内腔一倍是首轮建议。
- **端口与实际连接**：决定可达组织、路线、运输时间和共享瓶颈。

人体不设独立真元池。总量是内腔、外壁、在途、器官缓存和加工原料等唯一归属的汇总；预约、预计产物和动画不能再持有一份余额。器官缓存容量不参与经脉境界容量比。

## 经脉开拓与首脉起步

已确认：修炼起步时，经脉尚不能被意念调用，需要先聚集灵气、开拓首条经脉，才能使用该脉的主动调元能力。经脉本来存在，也可以自然存有少量游离态真元；经脉存在、存有真元和能够主动调用是不同条件。基础生命仍由身体维持，不以完成首脉开拓为前提。

开拓按经脉实例分别记录。完成首脉只开放这条经脉的取用能力，其余经脉仍需开拓；它们的自然储量不能直接加入主动线路的可用额度。开拓首先建立意念控制，也为后续扩容、提升吞吐和承受度提供成长入口。经脉完好度、开拓进度、结构能力与角色境界分别表达，不能由“完好”推断“已经开拓”，也不能由“有真元”推断“已经突破”。

建议用独立的入门聚灵／吐纳过程解决首脉启动：

1. 角色通过基础摄入能力聚集外界灵气，在内容指定的首脉入口进行局部积累与引导；该过程可在没有已开拓经脉时启动。
2. 灵气在局部转化、积累并推动经脉适应，逐步建立对意念的响应。转化后的真元只进入目标经脉内腔；开拓进度记录适应程度，不另持一份同额资源。
3. 开拓成功后启用该脉引元口，玩家才能配置主动取用、铺设意念线路并使用所连接的配方设施。成功本身不凭空补满储量。

聚灵的环境来源、摄入和转化由宿主与身体能力共同校验；尚未转化的灵气仍归摄入侧或环境持有。首脉选择由内容和实际身体入口决定，通用框架不固定肺经或人体命名。剂量、持续时间、材料、失败与中断处理仍待规则化。

后续开拓建议允许从已开拓经脉沿实际连接向相邻待开拓入口供给，执行专门的开拓过程；尚未开拓的经脉不能借此成为任意主动线路的中转。具体开拓方式与成本仍属于待细化内容。

内景中的资源显示、引元口和操作流程见[内景与经脉操作](Inner-World.md)。当前 `MeridianState` 只有内腔、外壁、疲劳和完好度，尚无开拓状态；现有运输算子也尚未执行开拓门槛。

## 相态与六境

| 境界 | 容量 / 理论液态参照容量 | 主要相态与作用阶段 |
|---|---|---|
| 醒灵 | 0.01 | 游离态；强化身体 |
| 引气 | 0.1 | 气态；逐步获得灼烧等基础五行附效 |
| 凝脉 | 1 | 液态；开始创造外部形态 |
| 固元 | 10 | 经脉内固态，健康通路中按原始速率移动 |
| 通灵 | 100 | 更高密度形态，具体性质仍需设计 |
| 化虚 | 1000 | 化虚相态，具体性质与转化规则仍需设计 |

六境及对应相态已纳入基础数据定义，化虚延续每境十倍容量比；这不代表相变、突破及各境玩法已经实现。混相可以共存，固态不因相态本身增加阻力，但不能绕过堵塞、断脉、容量和吞吐限制。

首轮数值建议：醒灵内腔 20 元、标准动作 2 元，满额不恢复约十招；外壁额外 20 元不计入即时十招。人体理论液态参照内腔与外壁各 2000 元，分子/分母覆盖相同参照空间。增加低密度储备空间必须同步增加参照，不能靠堆外壁容量假突破。最终绝对容量需与世界供给一起校准。

即时招数按已开拓且可达的实际储量计算；首脉起步的供元范围与容量配置仍需配合十招目标校准，不能把全身尚不可调用的储量计入预算。

## 利用与流动

肺经摄入并驯化的真元由自身意志驱动；其他生物声明等效输入能力。胃经可对接灵食，器官负责输入、加工、输出，肌肉可直接利用无属性真元。五行仍是具有属性的真元，不另造免费能源。

器官或材料的五行加工存在比例损耗。醒灵不自行使用五行，引气获得少量附效，凝脉才允许创造；高转换率不能跳过阶段限制。此前通用 70% 转换率已撤回，引气 5%–10%、凝脉 15%–25% 仅作候选。

真元输送参考水流，共享通路吞吐，污染表现为失控真元或阻力。提前调元改变实际局部分布，后续出招不重复等待已完成的路径。控制任务数暂按六境 1–6 项设计；途经经脉带来的反应时间受熟练度改善，不能消除真实运输时间。

离体真元逐级退化并回归环境。作用后的真元也回环境，真实生成物按材料规则保留；不能既保留产物里的真元又全额退还环境。所有损耗与释放都有明确去向。

## 已实现的经脉批次运输

`QiTransport.start` 沿既有有向连接发运，`BodyTimeAdvancement.apply` 在 `ACTIVE` 模式结算到达。支持经脉内腔与器官缓存任意组合，要求起止属于不同模块；组织端口没有真元账户，仍明确拒绝。同模块自搬运不开放，跨模块合法循环仍允许。器官缓存、加工中输入和输出规则见[配方执行](Technique-Addons.md)。

一次发运的顺序为：检查生命与版本 → 检查线路和两端状态 → 检查共享吞吐与目标预留容量 → 按相态/属性扣源内腔 → 计算到达时刻 → 原子保存扣源及唯一在途记录。目标此时没有获得真元，外壁也不会代付。新在途 ID 由身体版本和确定性避让后缀生成，不接受客户端指定。

| 规则 | 当前行为 |
|---|---|
| 两端共享吞吐 | 每个经脉或器官的端口收发共同使用自身 `throughputPerSecond`；换端口、换连接和反向发送也共享额度 |
| 申请吞吐 | 请求必须明确给出正数流量；不得超过源、目标各自扣除移动中预约后的剩余额度 |
| 目标容量 | `当前占用 + 所有入向在途货量 + 新批次 <= 模块容量`；器官当前占用包括缓存与加工输入；阻塞批次也预留容量 |
| 相态与属性 | 原样搬运，不加工、不退化；固态使用同一基础移动规则 |
| 通路状态 | 经脉须完整，器官及所属部位须有 HP；到达时再次检查，失能或破裂/断裂阻塞接收 |
| 到达条件 | 整批可入账才清除在途；目标满载则保留全部货物，不截断、不退款 |
| 同时到达 | 按到达毫秒、在途 ID 的字典序处理，不依赖存档列表顺序 |
| 阻塞恢复 | 保留 `BLOCKED_ROUTE` 或 `BLOCKED_CAPACITY`；相关状态变化后显式时间结算可重试，同毫秒也可执行 |

首轮可计算规则使用基础传播速度 **1 米/模拟秒**，到达延迟为：

```text
有效服务流量 = 申请吞吐 / (1 + 连接阻力)
批次耗时秒 = 连接距离 / 基础传播速度 + 货量 / 有效服务流量
到达毫秒 = 当前已结算毫秒 + max(1, ceil(批次耗时秒 × 1000))
```

两端预约吞吐在整个移动期保留，到达或进入阻塞后释放。因此这是保守的批次模型，尚无传送带连续流或流水线重叠的吞吐调度；以上数值未实机平衡。延迟用十进制运算向上取整，时钟溢出拒绝整次发运。源扣除或目标入账小到浮点无法记录时明确拒绝，不能创建免费在途或吞掉入账；一般数量运算仍沿用 `double` 的机器舍入规则。

`nextArrivalBoundary` 只返回移动中批次的最近到达；阻塞货物不安排周期重试。`nextEventBoundary` 合并寿尽、运输与加工完成，宿主无需逐帧移动真元。同毫秒先死亡、再加工完成、再运输到达；加工腾出空间也会在该事件重试受阻到达。`LIFESPAN_ONLY` 平移移动和加工中的未来时刻，保留剩余时长；已阻塞记录的历史时刻不变。

修改通路或容量前，宿主须先结算到修改时刻，再由后续受控改造/损伤算子改变状态。当前无中途泄漏、动态重算已发批次速度、取消/返航或自动多跳；没有泄漏规则时不会仅因 `LEAKING` 标记而凭空减去真元。

## 成长、突破与损伤

采用“有效负荷 → 疲劳 → 恢复巩固 → 能力变化”。轻度可恢复超载可缓慢提升韧性，该训练方法有上限；严重超载导致破裂或断裂及真元逸散。材料、功法与技术改造可以提供不同成长途径，来源独立但结果读取同一身体状态。

突破方向是特定增压功法、外壁储备达到 70% 以上、材料与强制相变，在持续适应后提升承受能力并吸收外壁储备用于结构成长。具体稳定时长、材料需求、储备去向与失败分级仍须算子化，不因临时灌入高阶真元直接判升境。

人体死亡方向为整体部位 HP 低于 20%，或头部 HP 为零。整体 HP 的汇总、非人关键部位及器官失能必须由模板与统一伤害规则明确，不能多次叠加局部与全身扣血。

长期缺乏养护可退化，短时用空不会立即掉境。修炼、非战斗工作和战斗共用相同身体事实，不为每种用途重写物理与伤害公式。
