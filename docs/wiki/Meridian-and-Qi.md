# 经脉、真元与成长

状态：以下产品方向已确认，标为建议的方案和数字仍待细化与实机平衡。[Java 17 核心](Data-Definitions.md)已提供构型、开脉运行与一次扩容、源经脉调用门槛、混相/多属性账本、批次运输、受控闭环、被动扩散、器官加工、组织能力/做功及可信活动原子提交。Human 已接入游炁提纯和真炁突破；引元口交互、通用工厂自动运行与长期训练成长仍待实现。

## 身体与经脉

经脉拥有天然倾向，同时允许后天改变。维持基础生命功能的前提下可改造身体；限制来自材料、操作、承载、恢复和控制难度，不由出生模板永久锁死路线。没有经脉的局部部位仍可存活，基础生命不依赖真元。

人体布局以中医经脉观念为灵感；左右实例、交汇和实际部位映射由模板声明。其他生物可有不同的部位与通路，不强制二十脉或人形肢体。

每条经脉包含：

- **内腔**：存留真元，具有局部容量、吞吐和承受度；该脉完成开拓后才能被意念主动取用。
- **外壁**：类似脂肪的长期储备，不能直接施招，须先动员进内腔。外壁容量约为内腔一倍是首轮建议。
- **端口与实际连接**：决定可达组织、路线、运输时间和共享瓶颈。

人体不设独立真元池。总量是内腔、外壁、在途、器官缓存和加工原料等唯一归属的汇总；预约、预计产物和动画不能再持有一份余额。器官缓存不能替代经脉内腔占用来满足人体开拓要求。

## 经脉开拓与首脉起步

已确认：修炼起步时，经脉尚不能被意念调用，需要先聚集灵气、开拓首条经脉，才能使用该脉的主动调元能力。经脉本来存在，也可以自然存有少量游离态真元；经脉存在、存有真元和能够主动调用是不同条件。基础生命仍由身体维持，不以完成首脉开拓为前提。

开拓按经脉实例分别记录。完成首脉只开放这条经脉的取用能力，其余经脉仍需开拓；它们的自然储量不能直接加入主动线路的可用额度。开拓首先建立意念控制，也为后续扩容、提升吞吐和承受度提供成长入口。经脉完好度、开拓进度、结构能力与角色境界分别表达，不能由“完好”推断“已经开拓”，也不能由“有真元”推断“已经突破”。

通过基础摄入、自然储元与专用开拓引导解决首脉启动，入口和数值由内容声明：

1. 角色通过基础摄入能力聚集外界灵气，经器官加工进入内容指定的经脉入口；该过程可在没有已开拓经脉时启动。
2. 产物通过自然流动积累在各经脉，再由专用开拓引导集中到目标，推动经脉适应并建立意念响应。Human 已确认肺经纳入后自动向全身经脉扩散；开拓进度只记录适应程度，真元仍由各实际账户持有。
3. 开拓成功后启用该脉引元口，玩家才能配置主动取用、铺设意念线路并使用所连接的配方设施。成功本身不凭空补满储量。

聚灵的环境来源、摄入和转化由宿主与身体能力共同校验；尚未转化的灵气仍归摄入侧或环境持有。首脉选择由内容和实际身体入口决定，通用框架不固定肺经或人体命名。[开脉运行](Meridian-Opening.md)已执行门槛、引导、连续适应、独立费用及中断处理；材料费用尚待实现。

自然扩散已允许未开脉被动接收、存留与流动，不解锁意念主动调用。Framework 按可信内容中的被动通路配置，校验状态、共享吞吐和容量，保持扣源、在途、到达的唯一归属，并按事件边界推进。Human 声明肺经入口、人体连接与速率；下方说明现有批次规则。

专用开拓引导沿可达路径把分散真元集中到所选目标，其权限和成本由开拓规则校验；普通主动线路仍要求源脉已开拓。Human 的任意选脉范围和阶段条件见[开拓需求](Meridian-Opening.md)。

资源显示、引元口及简易操作与规划中的 3D 入口见[经脉操作与 3D Addon](Inner-World.md)。`MeridianState.opening` 记录未开、进行中、已开阶段及进度，`BodySnapshot.opening_task` 保存运行事实；与真元余额、疲劳和完好度独立。实际任务按事件推进，具体约束见[开拓数据](Data-Definitions.md)。

## 相态与六境

| 境 | 名 | 经脉内相态 | `Realm.capacityRatio()` 基准密度 ρ | 一句话 |
|---|---|---|---|---|
| 1 | 游炁 | 游离态 | 0.01 | 炁在脉中零散游走，和外界的游离灵气是同一种状态 |
| 2 | 真炁 | 气态 | 0.1 | 炼成真炁，能在经脉里运转周天 |
| 3 | 化元 | 液态 | 1 | 炁化为元，真元有了重量，能在脉中流动 |
| 4 | 凝元 | 固态 | 10 | 元凝成实体 |
| 5 | 天纹 | 有序态 | 100 | 真元排列成纹，和天地的纹理同构 |
| 6 | 化虚 | 相干态 | 1000 | 天纹在高密度下耦合干涉，相长时极实，相消时化实为虚 |

六境名称、相态及上述解释已确定。相态由真元密度派生，区间边界为 `0.01 / 0.1 / 1 / 10 / 100 / 1000`；`QiPhase.ORDERED` 与 `QiPhase.COHERENT` 仍是派生枚举。密度是同一真元明细的状态，不是额外账本维度；同属性同区间合并时数量与体积守恒，混相可以共存。Human 的游炁至真炁相变使用可信活动原子更新候选密度与境界；天纹排列、相干干涉和重量作用仍待实现。固态不因相态本身增加阻力，但不能绕过堵塞、断脉、容量和吞吐限制。

首轮数值建议：游炁内腔液态参照体积 2000；游离态密度 `0.01` 时对应 20 元。标准动作费用仍按元计，满额不恢复约十招；外壁另有 2000 体积，不计入即时招式预算。容量始终按体积校验，低密度真元占用更多空间，不能通过临时改变体积或外壁容量绕过稳定上限。

Human 提供按境界解锁的经脉选择、体积门槛和每脉一次的稳定内腔扩容，具体数值以独立附属的[修炼要求](https://github.com/Kizunad/Kizuna-Meridian-Human-Addon/wiki/Cultivation)为准；框架契约见[开拓需求](Meridian-Opening.md)。容量增长不会改变已有真元密度，也不会扩大外壁。

即时招数按已开拓且可达的实际储量计算；首脉起步的供元范围与容量配置仍需配合十招目标校准，不能把全身尚不可调用的储量计入预算。

## 利用与流动

人体由肺器官摄入并炼化环境五行灵气，初始对各属性采用相同固定效率，统一产出无属性真元。Human 现有配方按 20% 炼化并送入同侧肺经，再自动沿实际连接向全身自然扩散；意念主动调元则在开拓后使用。肺器官的后天优化可分别提高某种输入属性的转换率，动态效率尚待实现；属性来源见[地形分布与肺炼化规划](Terrain-Qi-Generation.md)。其他生物声明等效输入能力，胃器官可对接灵食。器官负责输入、加工、输出，肌肉可直接利用无属性真元；五行仍是具有属性的真元，不另造免费能源。

器官或材料的五行加工存在比例损耗。游炁阶段强化身体，真炁获得少量灼烧等基础五行附效，化元才允许创造外部形态；高转换率不能跳过阶段限制。此前通用 70% 转换率已撤回，真炁 5%–10%、化元 15%–25% 仅作候选。

真元输送参考水流，共享通路吞吐，污染表现为失控真元或阻力。提前调元改变实际局部分布，后续出招不重复等待已完成的路径。控制任务数暂按六境 1–6 项设计；途经经脉带来的反应时间受熟练度改善，不能消除真实运输时间。

离体真元逐级退化并回归环境。作用后的真元也回环境，真实生成物按材料规则保留；不能既保留产物里的真元又全额退还环境。所有损耗与释放都有明确去向。

### 最小可流转单位

`QiAccounting.MIN_TRANSFER_QI` 为 **`1e-12 元`**，约束每条明细的新取用，整批总量达到单位不能夹带低于单位的明细。它用于隔离数量、体积反算产生的浮点尘埃，避免尘埃先进入空账户、之后无法加入非空目标；不会把所有余额四舍五入成该单位的整数倍。

自然扩散、开脉引导和吐纳比例配送跳过低于单位或无法实际扣动源余额的候选，不扣除对应数量、体积预算。主动运输、配方取料及环境摄入若明确请求低于单位的明细，以 `NUMERIC_LIMIT` 整笔拒绝，原账户不变。最小单位不能保证任意大余额都能体现加减，`QiAccounting.debit/credit` 的可表示性与溢出检查继续生效。

旧存档和转换输出仍可保存低于单位的正余额，不迁移、不删行，读取格式与 schema 不变。`combine` 和完整释放不按单位过滤真实资源：同种尘埃合并达到单位后可再次取用，转换损耗或死亡释放中的尘埃仍归相应释放账户；入账若会被目标余额完全吞掉，仍拒绝整个事务。按体积计算的费用沿用原算法和扣账校验，不按此单位减免费用；释放余额重新被取用时才检查单位。器官缓存中的微小转换产物只有积累到单位后才参与配送。

## 已实现的经脉批次运输

`QiTransport.start` 沿既有有向连接发运，`BodyTimeAdvancement.apply` 在 `ACTIVE` 模式结算到达。支持经脉内腔与器官缓存任意组合，要求起止属于不同模块；组织端口没有真元账户，仍明确拒绝。同模块自搬运不开放，跨模块合法循环仍允许。器官缓存、加工中输入和输出规则见[配方执行](Technique-Addons.md)。

一次发运的顺序为：检查生命与版本 → 检查线路和两端状态 → 检查共享吞吐与目标预留体积 → 按属性及实际密度扣源内腔 → 计算到达时刻 → 原子保存扣源及唯一在途记录。目标此时没有获得真元，外壁也不会代付。新在途 ID 由身体版本和确定性避让后缀生成，不接受客户端指定。

主动发运的源经脉必须为 `OPENED`，未开拓或开拓中返回 `MERIDIAN_UNOPENED`。目标经脉仍可未开拓，允许器官通过真实连接输入；[一次聚气](Gathering.md)使用这一规则先储存，再由后续开拓算子建立意念响应。

| 规则 | 当前行为 |
|---|---|
| 两端共享吞吐 | 每个经脉或器官的端口收发共同使用自身 `throughputPerSecond`；换端口、换连接和反向发送也共享额度 |
| 申请吞吐 | 请求必须明确给出正数流量；不得超过源、目标各自扣除移动中预约后的剩余额度 |
| 目标容量 | `当前体积占用 + 所有入向预约体积 + 新批次体积 <= 模块液态参照体积`；器官当前占用包括缓存与加工输入；阻塞批次也预留容量 |
| 密度与属性 | 原样搬运，不加工、不退化；密度保持不变，相态由到达后的密度重新派生 |
| 通路状态 | 经脉须完整，器官及所属部位须有 HP；到达时再次检查，失能或破裂/断裂阻塞接收 |
| 到达条件 | 整批可入账才清除在途；目标满载则保留全部货物，不截断、不退款 |
| 同时到达 | 按到达毫秒、在途 ID 的字典序处理，不依赖存档列表顺序 |
| 阻塞恢复 | 保留 `BLOCKED_ROUTE` 或 `BLOCKED_CAPACITY`；相关状态变化后显式时间结算可重试，同毫秒也可执行 |

首轮可计算规则使用基础传播速度 **1 米/模拟秒**，到达延迟为：

```text
有效服务流量 = 申请吞吐 / (1 + 连接阻力)
批次耗时秒 = 连接距离 / 基础传播速度 + 货量 / 有效服务流量
到达毫秒 = 当前已结算毫秒 + max(1, ceil(批次耗时秒 × 1000))
```

两端预约吞吐在整个移动期保留，到达或进入阻塞后释放。因此这是保守的批次模型，尚无传送带连续流或流水线重叠的吞吐调度；以上数值未实机平衡。延迟用十进制运算向上取整，时钟溢出拒绝整次发运。源扣除或目标入账小到浮点无法记录时明确拒绝，不能创建免费在途或吞掉入账；一般数量运算仍沿用 `double` 的机器舍入规则。

本轮吞吐仍按元/模拟秒计，密度只影响占用与预约体积。是否改为体积流量留待后续设计。

`nextArrivalBoundary` 只返回移动中批次的最近到达；阻塞货物不安排周期重试。`nextEventBoundary` 合并寿尽、运输、加工完成与当前可执行的自然扩散，宿主无需逐帧移动真元。同毫秒先死亡、再加工完成、再运输到达、最后自然发运；加工腾出空间也会在该事件重试受阻到达。`LIFESPAN_ONLY` 平移移动和加工中的未来时刻，保留剩余时长，不启动自然扩散；已阻塞记录的历史时刻不变。

## 已实现的自然扩散

内容在经脉间的有向 `Connection.passive_qi_flow` 中声明吞吐上限、最大批次、最小批次；省略即不自动扩散。两端必须是不同经脉，允许双向连接和循环。宿主需声明 `meridian:passive_qi_flow_v1` 能力，框架不内置生物 ID 或默认速率。

每次事件读取源内腔余额与目标已占容量，按容量占比差决定一批：

```text
源占比 = 源内腔体积占用 / 源稳定体积
目标占比 = (目标内腔体积占用 + 全部入向预约体积) / 目标稳定体积
平衡货量 = (源占比 − 目标占比) × 较小容量 / (1 + 较小容量 / 较大容量)
实际货量 = min(平衡货量, 最大批次, 源余额, 目标剩余空间)
```

源占比不高于目标、元数货量小于最小批次、通路失能或无共享吞吐时不发运。微小余量完整留在账户，避免循环图产生无限小事件；这里是有限精度的批次平衡。外壁不参与，属性和密度原样搬运。目标入向预约按其真实体积计入占用，尚未到源的货物不能提前再发。

按体积取货逐条应用[最小可流转单位](#最小可流转单位)与源扣款可表示性检查，被跳过的候选保留在源账户，后续明细仍可使用完整预算。最小批次检查作用于过滤后的整批货物；开脉引导复用同一取货规则。直接提交无法有效扣源的货物仍以 `NUMERIC_LIMIT` 拒绝，避免目标得到货物而源账户未减少。

发运复用普通运输的扣源、在途、容量预约、两端共享吞吐和耗时计算。主动取用仍校验源脉 `OPENED`；被动通路的许可来自可信构型。`QiTransport.availableThroughputPerSecond` 提供不预留资源的只读剩余吞吐，供器官出口等编排决定何时发运。

同一事件按连接 ID 稳定顺序，依次使用剩余预算，直到没有可发批次；当前没有分支公平调度。满载时可先向较空的下游发货，实际到达后才继续下一跳。平衡、阻塞或低于批次阈值时不周期唤醒；库存、容量、通路状态变化或运输到达后重新计算。单次长区间内产生的新到达也继续结算，因此与分段推进、保存恢复一致。

这已经支持生理性的多跳扩散；指定多段主动线路、优先级和持续供给任务仍属于后续工厂调度。

修改通路或容量前，宿主须先结算到修改时刻，再由后续受控改造/损伤算子改变状态。当前无中途泄漏、动态重算已发批次速度或取消/返航；没有泄漏规则时不会仅因 `LEAKING` 标记而凭空减去真元。

## 成长、突破与损伤

采用“有效负荷 → 疲劳 → 恢复巩固 → 能力变化”。轻度可恢复超载可缓慢提升韧性，该训练方法有上限；严重超载导致破裂或断裂及真元逸散。材料、功法与技术改造可以提供不同成长途径，来源独立但结果读取同一身体状态。

突破条件由内容附属配置，Framework 校验资源、做功、守恒及逐境转换。Human 的首轮实现是中焦八脉提纯、脾外壁燃料和连续60秒相变，门槛及失败规则见[中焦周天](https://github.com/Kizunad/Kizuna-Meridian-Human-Addon/wiki/Middle-Jiao-Cultivation)。后续境界的材料与结构成长另行设计；临时灌入高阶真元不会直接判升境。

人体死亡方向为整体部位 HP 低于 20%，或头部 HP 为零；阈值、关键部位及其引用由人体附属模组声明，主框架不写死“头部”或人体阈值。整体 HP 汇总、关键部位和器官失能的通用契约与伤害算子仍待实现，其他生物通过同一机制声明自身条件，不能多次叠加局部与全身扣血。

长期缺乏养护可退化，短时用空不会立即掉境。修炼、非战斗工作和战斗共用相同身体事实，不为每种用途重写物理与伤害公式。
